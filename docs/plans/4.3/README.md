## 六、执行原则

### 核心原则：能力同步，而非代码复制

**同步目标**：OpenCode 的测试验证能力 100% 同步到 Turbot

**不同步内容**：测试代码的具体实现（因语言差异需适配）

### 语言特性适配

| TypeScript 特性              | C++23 适配                           |
| ---------------------------- | ------------------------------------ |
| `async/await`                | `std::future`/`std::promise`         |
| `Promise<T>`                 | `std::future<T>`                     |
| `EventEmitter`               | `std::function` 回调 / `std::signal` |
| `jest.mock()` / `bun.mock()` | 依赖注入 / 接口抽象                  |
| `expect(x).toBe(y)`          | `REQUIRE(x == y)`                    |
| `describe/it`                | `TEST_CASE/SECTION`                  |
| `beforeEach/afterEach`       | `SetUp/TearDown` 或 RAII             |
| `import` 动态导入            | 编译期模板 / 工厂模式                |

### 执行要求

1. **能力对齐**：确保 Turbot 具备 OpenCode 同等的测试验证能力
2. **语言惯用**：使用 C++ 惯用写法，不生搬 TypeScript 模式
3. **验证 Turbot 实现**：测试目的是验证 Turbot 实现的正确性
4. **逐步验证**：每个子计划完成后立即验证，不累积问题
5. **代码审查**：每个子计划完成后进行 SPEARM 代码审查

### 测试优先原则

> **核心原则**：以测试框架为准，测试不通过时修复实现，而非修改测试

当测试框架检测出 Turbot 实现问题时：

```
测试失败 → 参考 OpenCode 实现 → 修改 Turbot 实现 → 测试通过
         ↑                                          │
         └──────────────────────────────────────────┘
```

**禁止行为**：

- ❌ 强行修改测试框架来适配 Turbot 的错误实现
- ❌ 跳过失败的测试用例
- ❌ 降低测试断言标准

**正确做法**：

- ✅ 参考 OpenCode 的正确实现
- ✅ 修复 Turbot 的实现代码
- ✅ 确保测试框架的权威性

**例外情况**：

- 仅当 Turbot 有意采用与 OpenCode 不同的设计决策时，才可调整测试
- 此类调整需要明确的 ADR (Architecture Decision Record) 支持

## 七、风险与缓解

| 风险           | 影响     | 缓解措施                 |
| -------------- | -------- | ------------------------ |
| C++23 兼容性   | 编译问题 | 使用 C++20 作为备选      |
| 异步测试复杂度 | 实现难度 | 使用 std::future 模拟    |
| 跨平台路径     | 平台差异 | 统一 std::filesystem     |
| 工作量较大     | 进度风险 | 分阶段执行，优先核心模块 |
