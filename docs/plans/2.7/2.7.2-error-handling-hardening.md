## 变更详情

### Fix-E1: `role_from_string()` 区分路径策略

**文件**: `libs/core/src/message/part.cpp:70-79`

**问题**: 当前对所有调用路径统一静默返回 `Role::User`，违反 2.6.2 计划 R-5 要求。

**当前代码**:

```cpp
Role role_from_string(std::string_view str) {
    static const std::unordered_map<std::string_view, Role> str_to_role = {
        {"user", Role::User},
        {"assistant", Role::Assistant},
        {"system", Role::System},
        {"tool", Role::Tool}
    };
    auto it = str_to_role.find(str);
    return it != str_to_role.end() ? it->second : Role::User;  // ← 静默降级
}
```

**修复方案**: 添加严格模式参数，区分两条调用路径：

```cpp
/// \param strict  若为 true，未知角色抛出 std::invalid_argument；
///                若为 false（默认），记录 WARN 并返回 Role::User（向后兼容）
Role role_from_string(std::string_view str, bool strict = false) {
    static const std::unordered_map<std::string_view, Role> str_to_role = {
        {"user", Role::User},
        {"assistant", Role::Assistant},
        {"system", Role::System},
        {"tool", Role::Tool}
    };
    auto it = str_to_role.find(str);
    if (it == str_to_role.end()) {
        if (strict) {
            throw std::invalid_argument(
                fmt::format("Unknown role string: '{}'. Valid: user, assistant, system, tool", str));
        }
        TURBOT_LOG_WARN("role_from_string: unknown role '{}', defaulting to User", str);
        return Role::User;
    }
    return it->second;
}
```

**调用方修改**：

- `part.cpp` 内部反序列化（`Part::from_json`）：保持 `strict = false`（向后兼容，读取历史数据）
- API 层输入解析（如未来 HTTP handler）：使用 `strict = true`（快速失败）

> **注意**: 如 2.7.1 结论指向需要同步更新 `session_loop.cpp` 中 role 相关调用，在此一并处理。

### Fix-E3: `execute_tool()` 捕获工具异常

**文件**: `libs/core/src/session/session_loop.cpp:300-321`

**问题**: `tool->execute(input, ctx)` 若抛出 C++ 异常，异常直接传播至 `process_llm_response()`，进而导致整个 session 崩溃，无法以 `ToolResult::error` 形式优雅降级。

**当前代码**:

```cpp
tool::ToolResult SessionLoop::execute_tool(const std::string& tool_name,
                                            const std::string& call_id,
                                            const nlohmann::json& input) {
    auto tool = tool::ToolRegistry::instance().get(tool_name);
    if (!tool) {
        return tool::ToolResult::error("Tool Not Found",
            fmt::format("Tool '{}' is not registered", tool_name));
    }

    // ...构建 ctx...

    return tool->execute(input, ctx);  // ← 异常直接传播
}
```

**修复**:

```cpp
tool::ToolResult SessionLoop::execute_tool(const std::string& tool_name,
                                            const std::string& call_id,
                                            const nlohmann::json& input) {
    auto tool = tool::ToolRegistry::instance().get(tool_name);
    if (!tool) {
        return tool::ToolResult::error("ToolNotFound",
            fmt::format("Tool '{}' is not registered", tool_name));
    }

    // ...构建 ctx...

    try {
        return tool->execute(input, ctx);
    } catch (const std::exception& e) {
        TURBOT_LOG_ERROR("Tool '{}' threw exception: {}", tool_name, e.what());
        return tool::ToolResult::error("ToolException", e.what());
    } catch (...) {
        TURBOT_LOG_ERROR("Tool '{}' threw unknown exception", tool_name);
        return tool::ToolResult::error("ToolException", "Unknown exception in tool execution");
    }
}
```

### Fix-E4: `sha256_file()` 区分错误类型

**文件**: `libs/utils/src/crypto_utils.cpp:474-481`

**问题**: 对"文件不存在"、"文件超过 100MB"和"IO 读取失败"三种情况统一返回空字符串 `""`，调用方无法区分，导致 `stop_tracking()` 将超大文件误判为"已修改为空"。

**当前代码**:

```cpp
std::string sha256_file(const std::filesystem::path& path) {
    auto content = turbot::utils::read_file(path.string());
    if (!content.has_value()) {
        return "";  // ← 无法区分失败原因
    }
    return sha256(*content);
}
```

**修复方案**: 引入强类型返回值（兼容方案，保留旧接口）：

**新增头文件声明** (`libs/utils/include/turbot/utils/crypto_utils.hpp`):

```cpp
/// Errors that can occur when hashing a file
enum class FileHashError {
    NotFound,    ///< File does not exist or cannot be opened
    TooLarge,    ///< File exceeds the 100MB size limit in read_file()
    IOError      ///< Other IO failure
};

using FileHashResult = std::variant<std::string, FileHashError>;

/// Hash a file, returning the SHA-256 hex string on success or a FileHashError on failure.
/// \see sha256_file (legacy overload returns "" on any failure)
[[nodiscard]] FileHashResult sha256_file_ex(const std::filesystem::path& path);
```

**新增实现** (`libs/utils/src/crypto_utils.cpp`):

```cpp
FileHashResult sha256_file_ex(const std::filesystem::path& path) {
    namespace fs = std::filesystem;
    std::error_code ec;

    // Check existence
    if (!fs::exists(path, ec) || ec) {
        return FileHashError::NotFound;
    }

    // Check size limit (same as read_file's 100MB cap)
    constexpr uintmax_t MAX_SIZE = 100ULL * 1024 * 1024;
    auto sz = fs::file_size(path, ec);
    if (!ec && sz > MAX_SIZE) {
        return FileHashError::TooLarge;
    }

    auto content = turbot::utils::read_file(path.string());
    if (!content.has_value()) {
        return FileHashError::IOError;
    }
    return sha256(*content);
}
```

**更新 `SnapshotManager::compute_file_hash()`** (`libs/core/src/snapshot/snapshot.cpp`):

```cpp
std::string SnapshotManager::compute_file_hash(const std::filesystem::path& path) {
    auto result = turbot::utils::crypto::sha256_file_ex(path);
    return std::visit([&](auto&& v) -> std::string {
        using T = std::decay_t<decltype(v)>;
        if constexpr (std::is_same_v<T, std::string>) {
            return v;
        } else {
            // Log with specific reason
            switch (v) {
                case turbot::utils::crypto::FileHashError::NotFound:
                    TURBOT_LOG_DEBUG("compute_file_hash: file not found: {}", path.string());
                    break;
                case turbot::utils::crypto::FileHashError::TooLarge:
                    TURBOT_LOG_WARN("compute_file_hash: file too large (>100MB): {}", path.string());
                    break;
                case turbot::utils::crypto::FileHashError::IOError:
                    TURBOT_LOG_ERROR("compute_file_hash: IO error reading: {}", path.string());
                    break;
            }
            return "";
        }
    }, result);
}
```

> **向后兼容性**: 保留原 `sha256_file()` 返回 `std::string` 的接口不变，标记为 deprecated 但不删除，避免其他调用方编译失败。

### Fix-E5: `SQLiteTransaction` 析构时重置 `active_`

**文件**: `libs/storage/src/sqlite_database.cpp:409-417`

**问题**: `rollback()` 在析构函数中抛出异常后被 catch 吞没，但 `active_` 未被重置为 `false`，导致 `is_active()` 在析构后仍返回 `true`，可能误导外部检查。

**当前代码**:

```cpp
SQLiteTransaction::~SQLiteTransaction() {
    if (active_.load() && is_db_alive() && db_) {
        try {
            rollback();
        } catch (...) {
            // Ignore errors in destructor  ← active_ 未重置
        }
    }
}
```

**修复**:

```cpp
SQLiteTransaction::~SQLiteTransaction() {
    if (active_.load() && is_db_alive() && db_) {
        try {
            rollback();
        } catch (...) {
            // Ignore errors in destructor; force-deactivate regardless
            active_.store(false);
        }
    }
}
```

> `rollback()` 成功时内部会将 `active_` 置 `false`，失败时由 catch 块强制置 `false`，两条路径均保持状态一致。
