## 目标

修复 `SessionLoop::agent_` 的数据竞争（Undefined Behavior），消除 A（架构）维度中的 MEDIUM 问题。

---

## 背景

### 数据竞争分析

`SessionLoop` 中 `agent_` 是 `std::shared_ptr<agent::Agent>`，被以下两条路径并发访问：

| 路径                                       | 操作                            | 保护                                     |
| ------------------------------------------ | ------------------------------- | ---------------------------------------- |
| `set_agent(std::shared_ptr<agent::Agent>)` | 写：`agent_ = std::move(agent)` | ❌ 无锁                                  |
| `build_llm_messages()`                     | 读：`agent_->prompt()`          | ❌ 无锁（在 `messages_mutex_` 获取之前） |
| `process_user_message()`                   | 读：`agent_->name()`            | ❌ 无锁                                  |
| `process_llm_response()`                   | 读：`agent_->name()`            | ❌ 无锁                                  |
| `execute_tool()`                           | 读：`agent_->name()`            | ❌ 无锁                                  |

`std::shared_ptr` 的赋值操作不是原子的（引用计数是线程安全的，但赋值本身不是），与并发读取构成 data race，属于 C++ UB。

## 变更详情

### Fix-C1: 为 `agent_` 添加专用互斥锁

**文件**: `libs/core/include/turbot/core/session/session_loop.hpp`

**新增成员变量**:

```cpp
private:
    // ...（已有成员）

    // agent_ 受 agent_mutex_ 保护，与 messages_mutex_ 不嵌套持有
    mutable std::mutex agent_mutex_;
    std::shared_ptr<agent::Agent> agent_;
```

> **锁顺序规约**：`agent_mutex_` 和 `messages_mutex_` 不得嵌套持有，以避免死锁。
>
> - `build_llm_messages()` 先快照 `agent_`（短暂持 `agent_mutex_`），再获取 `messages_mutex_`
> - 任何路径均不得在持有 `messages_mutex_` 时获取 `agent_mutex_`

---

### Fix-C2: 修改 `set_agent()` 加锁

**文件**: `libs/core/src/session/session_loop.cpp:51-53`

**当前代码**:

```cpp
void SessionLoop::set_agent(std::shared_ptr<agent::Agent> agent) {
    agent_ = std::move(agent);
}
```

**修复**:

```cpp
void SessionLoop::set_agent(std::shared_ptr<agent::Agent> agent) {
    std::lock_guard<std::mutex> lock(agent_mutex_);
    agent_ = std::move(agent);
}
```

### Fix-C3: 修改所有读取 `agent_` 的路径

**原则**: 不直接在长路径中持有 `agent_mutex_`，而是在使用前**快照到局部变量**，持锁时间控制在纳秒级。

#### `build_llm_messages()`（`session_loop.cpp:353-393`）

```cpp
std::vector<turbot::core::llm::LLMMessage> SessionLoop::build_llm_messages() const {
    // 快照 agent_（短暂持锁）
    std::shared_ptr<agent::Agent> local_agent;
    {
        std::lock_guard<std::mutex> lock(agent_mutex_);
        local_agent = agent_;
    }

    std::vector<turbot::core::llm::LLMMessage> result;

    // 使用 local_agent（无锁，safe）
    if (local_agent && local_agent->prompt().has_value()
        && !local_agent->prompt()->empty()) {
        result.push_back(llm::LLMMessage::system(*local_agent->prompt()));
    }

    // Copy messages under messages_mutex_ (独立，不与 agent_mutex_ 嵌套)
    std::vector<core::Message> snapshot;
    {
        std::lock_guard<std::mutex> lock(messages_mutex_);
        snapshot = messages_;
    }
    // ...（后续处理不变）
}
```

## 单元测试

**文件**: `tests/unit/session_loop_test.cpp`（新增并发测试）

```cpp
TEST_CASE("SessionLoop: concurrent set_agent and build_llm_messages - no data race",
          "[unit][session_loop][concurrency]") {
    auto loop = make_test_loop();
    auto agent1 = agent::AgentRegistry::instance().get("build");
    auto agent2 = agent::AgentRegistry::instance().get("explore");
    REQUIRE(agent1);
    REQUIRE(agent2);

    loop->set_agent(agent1);

    std::atomic<bool> stop{false};
    std::atomic<int> errors{0};

    // Thread A: 不断切换 agent
    std::thread writer([&]() {
        for (int i = 0; i < 1000 && !stop.load(); i++) {
            loop->set_agent(i % 2 == 0 ? agent1 : agent2);
        }
        stop.store(true);
    });

    // Thread B: 不断调用 build_llm_messages（间接读取 agent_）
    std::thread reader([&]() {
        while (!stop.load()) {
            try {
                // Indirectly exercises build_llm_messages via step()
                // (use a friend accessor or make build_llm_messages testable)
                (void)loop->build_llm_messages_for_test();
            } catch (...) {
                errors.fetch_add(1);
            }
        }
    });

    writer.join();
    reader.join();

    // No errors, no TSan reports
    CHECK(errors.load() == 0);
}
```

> **注**: 此测试依赖 ThreadSanitizer（`-fsanitize=thread`）检测 data race，建议在 CI 中以 TSan build 运行。
