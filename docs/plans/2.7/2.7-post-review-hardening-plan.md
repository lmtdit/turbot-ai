## 背景与动机

v2.6 完成了 Critical Bug 修复、Role::Tool 扩展、utils 模块整合和 SnapshotManager 性能优化，综合评分达到 **B+（7.2/10）**。

二次代码审查（逐行源码核实）发现以下问题：

1. **2.6.5 测试计划有三项未落地**（Fix-T1/T2/T3），且 Fix-T1/T3 的断言前提（SessionLoop 内置重试）尚未确认实现状态，需先厘清
2. **新发现两处 MEDIUM 级缺陷**：`agent_` 数据竞争（UB）、`execute_tool()` 异常不安全
3. **设计层面两处误解需纠正**：
   - `scan_files()` 缓存 `file_contents` 是有意为之，P 维度修复建议过于简化
   - `LoopResult::DoomLoop` 枚举不存在，2.6.5 计划文档验收标准有误
4. **`role_from_string` 未按 2.6.2 计划抛出异常**（R-5 偏差）
5. **错误处理静默降级模式**（`part_type_from_string`、`sha256_file`、事务析构）

v2.7 目标：修复以上问题，使综合评分从 B+（7.2）提升至 **A 级（≥8.5）**。

## 与 v3.0 的关系

v2.7 完成后，v3.0 协议系统开发将在以下改善基础上进行：

1. **异常安全的工具执行**（`execute_tool` 捕获异常）—— MCP 工具实现质量参差不齐，异常保护至关重要
2. **并发安全的 Agent 访问**（`agent_mutex_`）—— ACP 多智能体并发切换 Agent 时不产生 UB
3. **明确的 Snapshot 内存策略**（`max_cache_size_mb`）—— MCP 工具涉及大型代码库时不 OOM
4. **可靠的重试语义**（`RetryManager` 集成确认）—— 协议层调用失败时需精确的重试行为
