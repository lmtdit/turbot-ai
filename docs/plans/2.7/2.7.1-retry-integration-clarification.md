## 背景

### 问题一：`LoopResult::DoomLoop` 枚举不存在

2.6.5 计划文档验收标准中写道：

```
E2E-08：结果必须为 DoomLoop，不是模糊的"stop 或继续"
```

但实际 `LoopResult` 枚举仅有四个值（`session_loop.cpp:11-19`）：

```cpp
case LoopResult::Continue: return "continue";
case LoopResult::Stop:     return "stop";
case LoopResult::Compact:  return "compact";
case LoopResult::Error:    return "error";
```

doom loop 触发时实际返回 `LoopResult::Error`（`session_loop.cpp:251`）。已有 E2E-08b 正确验证了此行为。

### 问题二：Fix-T1/T3 断言前提未确认

2.6.5 Fix-T1/T3 要求 `call_count() >= 3`（2 次失败 + 1 次成功），这要求 `SessionLoop` 在收到 LLM error response 后**自动重试**。

但当前 `session_loop.cpp:209-213`：

```cpp
if (stream_result.has_error()) {
    if (on_error_) {
        on_error_(stream_result.error().value_or("Unknown error"), "llm_error");
    }
    return LoopResult::Error;  // 直接返回，无重试
}
```

`SessionLoop` 本身不重试。需要确认：`RetryManager` 是否被集成至 `LLM::stream()` 或 `SessionLoop` 的调用链中。


**两种可能结论**：

#### 结论 A：重试已实现（集成在 LLM::stream 或 process_llm_response 中）

- Fix-T1/T3 的 `call_count() >= 3` 断言**合理可行**
- 2.7.5 直接按 2.6.5 原计划修正断言
- 当前测试结果（`call_count() >= 1`）说明重试配置为 0 或测试未触发重试

#### 结论 B：重试未集成到 SessionLoop 调用链（RetryManager 存在但未使用）

- Fix-T1/T3 的 `call_count() >= 3` **目前不可能成立**
- 2.7.5 应将断言修正为：
  - E2E-07：验证 `result == Stop || result == Error`，`call_count() == 1`（即第一次错误直接终止）
  - ERR-01：同上，并添加错误回调验证

## 集成状态结论

**执行日期**: 2026-03-11

**结论：B — RetryManager 存在但未集成到 SessionLoop 调用链**

### 分析结果

**RetryManager 实现状态**：已完整实现（`retry_manager.hpp` + `retry_manager.cpp`），提供了：

- `with_retry<Func>()` 模板方法（指数退避 + 抖动）
- `is_retryable(APIError)` 判断（429、5xx 可重试）
- `calculate_delay()` / `apply_jitter()` 工具方法

**集成状态**：`RetryManager::with_retry()` **未被 SessionLoop 或 LLM::stream() 调用**。

`SessionLoop::process_llm_response()`（`session_loop.cpp:209-213`）在 LLM 返回错误后直接：

```cpp
if (stream_result.has_error()) {
    if (on_error_) on_error_(..., "llm_error");
    return LoopResult::Error;  // 直接返回，无重试
}
```

**2.7.5 测试目标值**：按**结论 B** 修正：

- E2E-07：`result == Error`，`call_count == 1`，`error_code == "llm_error"`
- ERR-01：同上
- ERR-02/05/06/07：同上
