## P0-1：Session 持久化 [CRITICAL]

> **状态**：✅ 已完成
> **实际完成文件**：`libs/core/include/turbot/core/session/session_store.hpp`、`libs/core/src/session/session_store.cpp`、`libs/core/src/session/session.cpp`、`tests/unit/session_store_test.cpp`
> **依赖**：无
> **影响版本**：v2.x + v3.0

### 问题描述

`libs/core/src/session/session.cpp` line 231-250 中三个方法均为占位：

```cpp
// This is a placeholder - in a real implementation, this would query the database
(void)id;
return std::nullopt;  // Session::get()
return {};            // Session::list()
return false;         // Session::delete()
```

同一文件 line 276-285 的 `Session::messages()` 也返回空：

```cpp
return {};  // placeholder
```

**影响链路**：

- v2.x：多 Session 管理不可用，会话历史无法从 DB 恢复
- v3.0：`ACP.load_session → Session::get() → nullopt → 抛异常`；`ACP.list_sessions → Session::list() → 永远空列表`；`ACP.fork_session` 永远失败

### 修复方向

`libs/storage/` SQLite 层已存在，接入路径：

1. 在 `session.cpp` 中注入 `IDatabase` 依赖（构造函数或 Setter）
2. 实现 `Session::get(id)` → `SELECT * FROM sessions WHERE id = ?`
3. 实现 `Session::list()` → `SELECT * FROM sessions ORDER BY created_at DESC`
4. 实现 `Session::delete(id)` → `DELETE FROM sessions WHERE id = ?`
5. 实现 `Session::messages(session_id)` → `SELECT * FROM messages WHERE session_id = ? ORDER BY seq`
6. 在 `SessionLoop` 启动时持久化新 Session，在每轮 step 后持久化消息

## P0-2：权限系统注入 [CRITICAL]

> **状态**：✅ 已完成
> **实际完成文件**：`libs/core/src/session/session_loop.cpp`（ask_permission 注入）、`tests/unit/permission_injection_test.cpp`
> **依赖**：P0-1（Session 层稳定）
> **影响版本**：v2.x + v3.0

### 问题描述

`libs/core/src/session/session_loop.cpp` line 700 构建 `ToolContext` 时，`ask_permission` 回调从未设置：

```cpp
tool::ToolContext ctx;
ctx.session_id        = session_.id();
ctx.message_id        = fmt::format("msg_{}", ...);
ctx.agent             = local_agent ? local_agent->name() : "unknown";
ctx.call_id           = call_id;
ctx.abort_flag        = abort_flag_;
ctx.working_directory = session_.info().directory;
// ask_permission 从未设置 ← 所有工具跳过权限确认
```

各工具（read/write/edit/bash/glob/grep/list）均有如下守卫：

```cpp
if (!ctx.ask_permission) {
    return PermissionResult::allow();  // 直接放行，permission.cpp 规则引擎从未触发
}
```

**OpenCode 对比**：完整闭环为 `permission.asked` EventBus 事件 → ACP `requestPermission()` → 用户确认 → 权限回复

### 修复方向

1. 在 `SessionLoop` 中增加权限回调注入点（构造时或 `run()` 前）
2. 实现 `ask_permission` lambda：
   - 通过 EventBus 发布 `permission.asked` 事件，携带工具名、参数、session_id
   - 等待 `permission.granted` / `permission.denied` 事件回复（使用 `std::promise` / `condition_variable`）
3. ACP 侧（`acp/agent.cpp`）监听 `permission.asked`，向客户端发送 `requestPermission` 通知
4. ACP 侧处理客户端回复，发布 `permission.granted` 或 `permission.denied`

### 验收标准

- [x] 编译通过
- [x] write/bash 工具触发时，ACP 客户端收到 `requestPermission` 事件
- [x] 用户拒绝后工具中止执行
- [x] 用户允许后工具正常执行
- [x] `permission.cpp` 规则引擎中的 always_allow/always_deny 规则生效
