## P1-2：ACP cancel() 中断信号

> **状态**：📋 待启动
> **依赖**：P0-1（见 4.0.1）
> **影响版本**：v3.0

### 问题描述

`libs/core/src/acp/agent.cpp` line 439-448，`cancel()` 方法为 no-op stub：

```cpp
void TurbotACPAgent::cancel(const CancelNotification& notif) {
    // No-op: cancel is handled implicitly via SessionLoop::stop()...
    // This stub satisfies the interface contract.
}
```

`SessionLoop` 无 stop handle 暴露给 `agent.cpp`，导致中断信号无法传递。

### 修复方向

1. 在 `SessionLoop` 中暴露 `stop()` 方法（或通过 `abort_flag_` 的公开接口）
2. `TurbotACPAgent` 持有对应 session 的 `SessionLoop` 弱引用或 stop callback
3. `cancel()` 内通过 session_id 查找对应 loop，调用 `stop()`

### 验收标准

- [ ] 编译通过
- [ ] 发送 cancel 通知后，运行中的 SessionLoop 在下一个工具调用边界停止
- [ ] cancel 后 ACP 侧收到正确的结束状态事件
- [ ] 相关单元测试通过，新增文件覆盖率 ≥ 85%

## P1-3：set_on_tool_result diff 内容修复

> **状态**：📋 待启动
> **依赖**：无
> **影响版本**：v3.0

### 问题描述

`libs/core/src/acp/agent.cpp` line 384-390，edit 工具完成时 diff 块内容为空：

```cpp
// rawInput not available in result callback; emit empty-path diff
content.push_back({{"type", "diff"},
                   {"path", ""},
                   {"oldText", ""},
                   {"newText", ""}});
```

`load_session` 历史回放路径（line 609-615）已正确从 `args` 提取，弹流路径是主要问题。

### 修复方向

在工具结果回调中传入 `rawInput`（工具调用的原始参数）：

1. 扩展 `set_on_tool_result` 回调签名，携带 `tool_call_input`（含 `filePath`/`oldString`/`newString`）
2. 在 edit 工具完成时，从 `rawInput` 提取 `filePath`、`oldString`、`newString`
3. 生成真实 diff 块：`{"type": "diff", "path": filePath, "oldText": oldString, "newText": newString}`

### 验收标准

- [ ] 编译通过
- [ ] edit 工具执行后，ACP 客户端收到含真实路径和 diff 内容的事件
- [ ] IDE 侧可正确渲染文件变更 diff
