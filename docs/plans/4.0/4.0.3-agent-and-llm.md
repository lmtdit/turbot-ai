## P1-6：Provider 初始化与端到端 LLM 验证

> **状态**：✅ 已完成
> **实际完成文件**：`apps/turbot-cli/src/commands.cpp`（init_provider_from_config + set_provider/set_model）、`tests/integration/llm_provider_e2e_test.cpp`
> **依赖**：无（独立问题，P1-1 的前置）
> **影响版本**：v2.x + v3.0

### 问题描述

当前 `apps/turbot-cli/src/commands.cpp` 的 `run_session()` 从未为 `SessionLoop` 注入 Provider 和 Model，导致 `process_llm_response()` 的守卫逻辑直接返回 `LoopResult::Error`：

```cpp
// session_loop.cpp line 326-331
LoopResult SessionLoop::process_llm_response() {
    if (!provider_ || model_id_.empty()) {
        // 始终命中此分支 — 实际 LLM 调用从未发生
        return LoopResult::Error;
    }
    // ...
}

// commands.cpp run_session() — 缺失的注入代码
core::session::SessionLoop loop(session);
loop.set_agent(agent);
// ← 从未调用 loop.set_provider() / loop.set_model()
```

同时，`ProviderManager` 单例从未初始化，导致 Agent.execute() 内无法通过 `get_default_provider()` 获取 Provider 实例（P1-1 的依赖）。

`.turbot/turbot.json` 已包含完整的 bailian provider 配置（api_key + base_url + default_model），但从未被加载。

### 修复方向

**1. 在 `commands.cpp` 中加载配置并初始化 Provider**

```cpp
#include <turbot/core/provider/impl/bailian_provider.hpp>
#include <turbot/core/provider/provider_manager.hpp>
#include <nlohmann/json.hpp>
#include <fstream>

void init_provider_from_config(const std::string& config_path) {
    std::ifstream f(config_path);
    if (!f.is_open()) return;
    auto cfg = nlohmann::json::parse(f);

    for (const auto& p : cfg.value("providers", nlohmann::json::array())) {
        if (p.value("type", "") == "bailian") {
            provider::ProviderConfig config;
            config.api_key  = p.value("api_key", "");
            config.base_url = p.value("base_url", "");

            auto bailian = std::make_shared<provider::BailianProvider>(config);
            auto& pm = provider::ProviderManager::instance();
            pm.register_provider(bailian);
            pm.set_default_provider("bailian");
            break;
        }
    }
}
```

在 `run_session()` 和 `run_acp()` 开头调用 `init_provider_from_config(".turbot/turbot.json")`。

**2. 在 `run_session()` 中为 SessionLoop 注入 Provider 和 Model**

```cpp
core::session::SessionLoop loop(session);
loop.set_agent(agent);

auto& pm = core::provider::ProviderManager::instance();
if (auto prov = pm.get_default_provider()) {
    loop.set_provider(prov->get());
    loop.set_model("qwen3-coder-plus");
}
```

**3. 添加端到端集成测试**（`tests/integration/llm_provider_e2e_test.cpp`）


## P1-1：内置 Agent 实现

> **状态**：✅ 已完成
> **实际完成文件**：`libs/core/src/agent/builtin/build_agent.cpp`、`plan_agent.cpp`、`explore_agent.cpp`、`tests/unit/builtin_agents_llm_test.cpp`
> **依赖**：P0-1, P0-2（见 4.0.1），**P1-6**
> **影响版本**：v2.x + v3.0

### 问题描述

三个内置 Agent 均为占位，只返回格式化字符串：

```cpp
// build_agent.cpp / explore_agent.cpp / plan_agent.cpp
// Build/Explore/Plan agent is a placeholder for now
return ExecuteResult::ok(fmt::format("... processed..."));
```

`task_tool.cpp` line 167 直接调用 `agent->execute(exec_params)`，导致 `TaskTool` 派发子任务时获得的是占位结果，而非真实 LLM 输出。

### 修复方向

参考 OpenCode `agent.ts` 子 Agent 路由体系，每个 Agent 的 `execute()` 内部通过子 `SessionLoop` 接入真实 LLM：

**通用模式**（三个 Agent 共享）：

```cpp
ExecuteResult XxxAgent::execute(const ExecuteParams& params) {
    auto& pm = provider::ProviderManager::instance();
    auto provider_opt = pm.get_default_provider();
    if (!provider_opt) {
        return ExecuteResult::error("No provider configured");
    }

    session::SessionLoop sub_loop(params.session_id);
    sub_loop.set_provider(provider_opt->get());
    sub_loop.set_model(/* agent 专属模型，或 provider 默认模型 */);
    sub_loop.set_agent(shared_from_this());  // 注入自身（携带 info_.prompt）

    auto result = sub_loop.run(params.prompt);
    if (result == session::LoopResult::Error) {
        return ExecuteResult::error("LLM execution failed");
    }
    auto last_text = sub_loop.messages().back().get_text();
    return ExecuteResult::ok(last_text);
}
```

**各 Agent 专属系统提示词**（设置在 `info_.prompt`）：

- **BuildAgent**：「你是代码构建专家。使用 bash/write_file 工具完成编译、测试、修复任务。」
- **ExploreAgent**：「你是代码探索专家（只读）。使用 read_file/glob/grep/list_dir 分析代码，不得写入任何文件。」
- **PlanAgent**：「你是任务规划专家。分析请求并输出详细的分步执行计划，不调用任何工具。」

**工具权限**（已在各 Agent 构造函数中定义，保持不变）：

- BuildAgent：允许所有工具
- ExploreAgent：只允许 read_file/bash(ls/find/grep/git)，其余 Deny
- PlanAgent：无工具调用权限
