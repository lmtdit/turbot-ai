## 目标

将 MCP 配置读写融入现有 `Config` 系统，工具变更/状态变更/浏览器失败事件接入 `EventBus`，支持 App 启动时自动初始化 MCP 服务器，以及配置热重载。

## 实施步骤

### 步骤 1：Config 路径约定与辅助函数

**配置文件格式**（`~/.turbot/config.json`）：

```json
{
  "mcp": {
    "playwright": {
      "type": "local",
      "command": ["npx", "-y", "@playwright/mcp"],
      "enabled": true,
      "timeout": 30000
    },
    "my-remote": {
      "type": "remote",
      "url": "https://mcp.example.com/",
      "oauth": true,
      "enabled": true
    },
    "custom-headers": {
      "type": "remote",
      "url": "https://mcp2.example.com/",
      "headers": { "Authorization": "Bearer token123" },
      "enabled": true
    }
  }
}
```

**辅助函数**（`libs/core/src/mcp/config_bridge.cpp`）：

```cpp
// load_mcp_configs()：遍历 Config "mcp" 键，构造 MCPClientConfig 列表
// Config::instance().get<nlohmann::json>("mcp") 获取整个 mcp 对象
// 遍历每个键值对，转换为 MCPClientConfig
std::vector<MCPClientConfig> load_mcp_configs();

// MCPManager 初始化入口（App 启动时调用）
void initialize_mcp_from_config();

// 注册 Config watch 回调（热重载）
void register_mcp_config_watch();
```

**验收**：`load_mcp_configs()` 正确解析上述三种配置格式

### 步骤 2：EventBus 事件定义与发布

**MCP EventBus 事件**（对齐 OpenCode Bus 事件命名，全部使用点路径）：

| 事件名                      | Payload 类型       | 触发时机                          | 对齐 OpenCode           |
| --------------------------- | ------------------ | --------------------------------- | ----------------------- |
| `"mcp.tools.changed"`       | `{server: string}` | `tools/list_changed` 通知收到后   | `MCP.ToolsChanged`      |
| `"mcp.status.changed"`      | `{server, status}` | MCPClient status 变更时           | 无直接对应，Turbot 扩展 |
| `"mcp.browser.open.failed"` | `{mcpName, url}`   | `authenticate()` 打开浏览器失败时 | `MCP.BrowserOpenFailed` |

**事件发布代码**（位于 manager.cpp 中相应位置）：

```cpp
// tools/list_changed 触发
EventBus::instance().publish<nlohmann::json>("mcp.tools.changed",
    nlohmann::json{{"server", server_name}});

// authenticate 浏览器失败
EventBus::instance().publish<nlohmann::json>("mcp.browser.open.failed",
    nlohmann::json{{"mcpName", mcp_name}, {"url", auth_url}});
```

**Agent Loop 订阅示例**（说明用途，不在本计划中实现）：

```cpp
EventBus::instance().subscribe<nlohmann::json>("mcp.tools.changed",
    [](const Event<nlohmann::json>& e) {
        MCPManager::instance().sync_tools_to_registry();
    });
```

**验收**：`EventBus` 订阅 `"mcp.tools.changed"` 能正确收到事件

### 步骤 3：App 启动集成

**App 初始化流程**（`app/app.cpp` 或对应启动文件中调用）：

```
App::start()
  → initialize_mcp_from_config()
      → load_mcp_configs()
      → MCPManager::instance().initialize(configs)
          → 对每个 enabled=true 的配置，调用 add()
  → register_mcp_config_watch()
      → Config::instance().watch("mcp", [](const nlohmann::json& new_val) {
            // 重新加载，对比新旧配置
            // 新增 → add()
            // 删除 → remove()
            // 变更 → remove() + add()
        })
```

**配置热重载规则**：

- 新增 server → `MCPManager::add(name, new_config)`
- 删除 server → `MCPManager::remove(name)`
- 修改 enabled=false → `MCPManager::disconnect(name)`
- 修改其他参数 → `MCPManager::remove(name)` + `MCPManager::add(name, new_config)`

**验收**：

- App 启动后 `MCPManager::instance().status()` 含所有 enabled 服务器
- 配置文件变更后 MCPManager 自动响应

## 验收标准

1. App 启动时，`MCPManager::initialize()` 从 Config 读取并连接所有 `enabled=true` 的服务器
2. `tools/list_changed` 通知触发 EventBus 发布 `"mcp.tools.changed"`，可被订阅
3. Config `watch("mcp", ...)` 支持热重载（新增/删除/修改服务器）
4. 三种配置类型（local/remote with oauth/remote with headers）均能正确解析
5. MCP 阶段集成测试全部通过
