## 目标

将 LSP 诊断事件接入 `EventBus`，将 LSP 功能（diagnostics/hover/definition/references/workspace_symbol）注册为 Agent 可调用工具，完成 LSP 子系统与 Agent Loop 的集成。

## 实施步骤

### 步骤 1：EventBus 事件发布（在 LSPClient/LSPManager 中完善）

**LSP EventBus 事件**（对齐 OpenCode LSP 事件）：

| 事件名                     | Payload                                            | 触发时机                                                             | 对齐 OpenCode                 |
| -------------------------- | -------------------------------------------------- | -------------------------------------------------------------------- | ----------------------------- |
| `"lsp.client.diagnostics"` | `{"server_id": "clangd", "path": "/abs/path.cpp"}` | diagnostics debounce 150ms 后                                        | `LSPClient.Event.Diagnostics` |
| `"lsp.updated"`            | `{}`                                               | 新客户端启动成功时（对齐 OpenCode `Bus.publish(Event.Updated, {})`） | `LSP.Event.Updated`           |

**发布位置**：

`client.cpp` 中 `publishDiagnostics` 处理器（debounce 后）：

```cpp
// 150ms debounce 触发后：
EventBus::instance().publish<nlohmann::json>("lsp.client.diagnostics",
    nlohmann::json{{"server_id", server_id_}, {"path", file_path}});
```

`manager.cpp` 中新客户端启动成功后：

```cpp
// LSPClient::create() 成功返回后：
clients_.push_back(std::move(client));
EventBus::instance().publish<nlohmann::json>("lsp.updated", nlohmann::json{});
// 对齐 OpenCode：仅在新客户端启动成功时（not on reconnect，not on config change）
```

**验收**：订阅 `"lsp.client.diagnostics"` 和 `"lsp.updated"` 能正确收到事件

### 步骤 2：注册 LSP 工具到 ToolRegistry

**工具清单**（对齐 3.0 规划文档 3.7.2 节）：

| 工具名                 | 功能                                   | 输入参数                                  |
| ---------------------- | -------------------------------------- | ----------------------------------------- |
| `lsp_diagnostics`      | 获取指定文件诊断（含 pretty 格式化）   | `file: string`                            |
| `lsp_hover`            | 获取光标处悬停信息                     | `file: string, line: int, character: int` |
| `lsp_definition`       | 跳转到定义                             | `file: string, line: int, character: int` |
| `lsp_references`       | 查找引用（`includeDeclaration: true`） | `file: string, line: int, character: int` |
| `lsp_workspace_symbol` | 工作区符号查找（最多10条，已过滤类型） | `query: string`                           |

**`lsp_workspace_symbol` 过滤规则**（对齐 OpenCode `kinds`）：

```
过滤 SymbolKind：Class(5), Function(6), Method(11), Interface(12),
                  Variable(13), Constant(14), Struct(23), Enum(10)
最多返回 10 条
```

**工具注册入口**：

```cpp
// libs/core/include/turbot/core/lsp/tools.hpp
namespace turbot::core::lsp {
    // 注册所有 LSP 工具到 ToolRegistry
    // 调用时机：LSPManager::initialize() 之后
    void register_lsp_tools();
}
```

**各工具实现要点**：

#### `lsp_diagnostics`

```cpp
// 输入 schema：{"type": "object", "properties": {"file": {"type": "string"}}, "required": ["file"]}
// 执行逻辑：
// 1. LSPManager::instance().touch_file(file, true)  // 触发 LSP + 等待诊断
// 2. 获取所有客户端的诊断
// 3. 格式化输出（每条诊断使用 pretty_diagnostic()）
// 4. 返回 JSON 字符串（多条诊断合并）
```

#### `lsp_hover`

```cpp
// 执行逻辑：
// 1. LSPManager::instance().touch_file(file)
// 2. auto result = LSPManager::instance().hover(file, {line, character}).get()
// 3. 返回 hover.contents（string）或 "No hover information"
```

#### `lsp_definition` / `lsp_references`

```cpp
// 执行逻辑：
// 1. touch_file + 调用对应 LSPManager 方法
// 2. 格式化 Location 列表："{file}:{line+1}:{char+1}"
// 3. 返回 JSON 数组字符串
```

#### `lsp_workspace_symbol`

```cpp
// 执行逻辑：
// 1. symbols = LSPManager::instance().workspace_symbol(query).get()
// 2. 过滤 kind in {5,6,11,12,13,14,23,10}
// 3. 取前 10 条
// 4. 格式化："{name} ({kind_name}) at {location}"
```

### 步骤 3：diagnostics pretty 格式规范

**格式**（对齐 OpenCode `LSP.Diagnostic.pretty`）：

```
ERROR [1:5] use of undeclared identifier 'foo'
WARN [10:3] unused variable 'bar'
INFO [15:1] consider using 'auto'
HINT [20:8] possible null dereference
```

**severity 映射**：

```cpp
const char* severity_name(int severity) {
    switch (severity) {
        case 1: return "ERROR";
        case 2: return "WARN";
        case 3: return "INFO";
        case 4: return "HINT";
        default: return "UNKNOWN";
    }
}
// 格式："{SEVERITY} [{line+1}:{char+1}] {message}"
```

### 步骤 4：集成测试

```cpp
// tests/integration/lsp/test_lsp_tools.cpp

TEST(LSPTools, ToolsRegistered) {
    LSPManager::instance().initialize();
    register_lsp_tools();
    EXPECT_TRUE(ToolRegistry::instance().has("lsp_diagnostics"));
    EXPECT_TRUE(ToolRegistry::instance().has("lsp_hover"));
    EXPECT_TRUE(ToolRegistry::instance().has("lsp_definition"));
    EXPECT_TRUE(ToolRegistry::instance().has("lsp_references"));
    EXPECT_TRUE(ToolRegistry::instance().has("lsp_workspace_symbol"));
}

TEST(LSPTools, SKIP_IF_NO_CLANGD_WorkspaceSymbolFiltered) {
    // 对 C++ 项目执行 lsp_workspace_symbol
    // 断言结果 <= 10 条，且 kind 均在过滤列表中
}

TEST(LSPTools, EventBusLspUpdated) {
    bool received = false;
    EventBus::instance().subscribe<nlohmann::json>("lsp.updated",
        [&](const auto&) { received = true; });
    // 触发客户端启动
    LSPManager::instance().touch_file("some_cpp_file.cpp");
    std::this_thread::sleep_for(std::chrono::milliseconds(500));
    EXPECT_TRUE(received);
}
```

## 验收标准

1. `ToolRegistry::instance().has("lsp_diagnostics")` 为 true
2. 诊断更新后 EventBus 收到 `"lsp.client.diagnostics"` 事件
3. `lsp_workspace_symbol` 结果最多 10 条，种类已过滤
4. 新客户端启动成功时（仅一次）发布 `"lsp.updated"` 事件
5. `lsp_diagnostics` 工具输出 pretty 格式字符串
