### 步骤 2：定义 ITransport 抽象接口（transport.hpp）

```cpp
class ITransport {
public:
    virtual ~ITransport() = default;
    virtual std::future<void> connect() = 0;
    virtual std::future<JsonRpcResponse> send_request(
        const std::string& method,
        const nlohmann::json& params = nlohmann::json::object()
    ) = 0;
    virtual void send_notification(
        const std::string& method,
        const nlohmann::json& params = nlohmann::json::object()
    ) = 0;
    virtual void on_notification(
        const std::string& method,
        std::function<void(const nlohmann::json&)> handler
    ) = 0;
    virtual std::future<void> close() = 0;
    virtual int pid() const noexcept { return -1; }  // 仅 StdioTransport 返回有效 PID
};
```

**验收**：抽象接口编译通过，含纯虚析构

### 步骤 3：实现 StdioTransport（stdio_transport.cpp）

**设计要点**：

- `fork + execvp` 启动子进程，持有 stdin/stdout/stderr pipe fd
- 独立 io 读线程：持续从 stdout 读取 newline-delimited JSON，按 `id` 派发到 pending `promise`
- 通知消息（无 `id` 字段）：调用对应 `on_notification` 处理器
- stderr 异步日志（对齐 OpenCode `transport.stderr?.on("data", ...)`）：**对含 `Authorization`/`Bearer`/`token`/`secret` 关键字的行脱敏后再输出日志**
- 进程退出时清理所有 pending futures（以 error response 完成）
- `pid()` 返回子进程 PID（供 `MCPManager` 清理孙进程，对齐 OpenCode `descendants(pid)` + SIGTERM 逻辑）
- **写 fd 互斥保护**：持有 `write_mutex_`（`std::mutex`）后再写入 stdin pipe，防止多线程并发调用 `send_request()`/`send_notification()` 时消息帧交错

**消息帧格式**（Newline-Delimited JSON）：

```
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}\n
```

**实施内容**：

1. `connect()`：fork + execvp，启动读线程
2. `send_request()`：原子自增 id；`std::lock_guard<std::mutex> lock(write_mutex_)` 后写入 stdin pipe；注册 promise，返回 future
3. `send_notification()`：`std::lock_guard<std::mutex> lock(write_mutex_)` 后写入 stdin pipe，无 id
4. 读线程：readline → JSON 解析 → 按 id 分发或调用通知 handler
5. `close()`：关闭 stdin fd，发 SIGTERM，等待进程退出

**验收**：

- Mock 子进程（echo server）测试请求/响应往返
- 不合法 JSON 不 crash，记录错误日志并继续

### 步骤 4：实现 SSETransport（sse_transport.cpp）

**设计要点**：

- 建立 SSE 长连接（`GET {url}` with `Accept: text/event-stream`）
- 通过 `HttpClient::request_stream()` 接收 SSE 推送消息
- 请求通过独立 POST `{url}` 发出
- SSE `data:` 字段解析为 JSON-RPC 消息，分发逻辑与 StdioTransport 一致

**实施内容**：

1. `connect()`：建立 SSE 连接，启动读循环
2. `send_request()`：POST `{url}` + JSON body，注册 promise 等待 SSE 推送
3. SSE 读循环：解析 `data: {...}` 行，触发分发

**验收**：

- Mock SSE 服务器（HTTP test double）测试完整请求-响应周期
- SSE 连接断开时自动触发 close 清理

---

### 步骤 5：实现 HttpTransport（http_transport.cpp，含 SSE fallback）

**设计要点**：

- 先尝试 `StreamableHTTP`：POST `{url}`，Content-Type: application/json，期望响应 `application/json`（同步响应）
- 降级到 SSETransport 的触发条件（对齐 OpenCode `StreamableHTTPClientTransport` → `SSEClientTransport` fallback）：
  1. `connect()` 阶段收到 `Content-Type: text/event-stream` 响应 → 切换 SSE 模式
  2. `connect()` 超时（30s 内无任何响应）→ 降级到 SSE
  3. 收到非 200 且非 `text/event-stream` 的响应（如 404/401）→ **报错，不降级**（服务端配置错误，非协议不匹配）
  4. 收到 5xx 响应 → **报错，不降级**（服务端内部错误，降级无意义）
- 降级时所有挂起的 pending promises 以 error response 完成（复用进程退出清理逻辑）
- 降级策略：首次 `connect()` 时检测，一旦确定协议类型后固定，不再重试

**实施内容**：

1. `connect()`：尝试 StreamableHTTP，按上述条件判断是否降级到 SSE 模式
2. `send_request()`：根据已确定的协议模式路由

**验收**：

- 对支持 Streamable HTTP 的 Mock 服务器，优先使用 HTTP 模式
- 对仅 SSE 服务器（返回 `text/event-stream`），自动降级
- 对 404/5xx 服务器，报错不降级（错误 response 完成所有 pending futures）
- connect() 超时 30s，自动降级到 SSE
