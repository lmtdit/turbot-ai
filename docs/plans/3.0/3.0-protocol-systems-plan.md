### 1.2 关键技术差异

| 维度           | OpenCode (TypeScript)                                                  | Turbot (C++23)                                | 实现策略                                                      |
| -------------- | ---------------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------- |
| MCP 传输       | 官方 SDK（3种传输类）                                                  | 无 C++ SDK                                    | 基于 `HttpClient`(SSE/HTTP) + subprocess pipe(stdio) 手工实现 |
| MCP 连接降级   | StreamableHTTP → SSE fallback                                          | —                                             | 按顺序尝试，首个成功即止                                      |
| MCP 工具命名   | `clientName.replace(/[^a-zA-Z0-9_-]/g,"_")`                            | —                                             | 对齐 OpenCode 正则，`{server}_{tool}`                         |
| LSP framing    | `vscode-jsonrpc`（Content-Length header）                              | —                                             | 手工解析 `Content-Length: N\r\n\r\n`                          |
| LSP debounce   | `setTimeout(..., 150)`；`waitForDiagnostics` 超时 3000ms               | —                                             | `std::chrono` + condition_variable；3s 超时                   |
| LSP 服务器数量 | 8种（Deno/TS/Vue/ESLint/Oxlint/Biome/Gopls/Clangd/Python/...）         | —                                             | 优先实现 Clangd/Pyright/Gopls 3种                             |
| ACP 事件驱动   | `sdk.global.event()` SSE 流 → `handleEvent(payload)`                   | —                                             | 订阅 Turbot `EventBus`，处理 session 事件                     |
| ACP 历史回放   | `loadSession` 调用 `processMessage()` 逐条回放历史到 ACP 客户端        | —                                             | 弥补 OpenCode 缺陷4 的超集功能                                |
| ACP 权限系统   | `permission.asked` 事件 → `requestPermission()` → `permission.reply()` | —                                             | EventBus `permission.asked` → ACPAgent 回调                   |
| 并发模型       | Promise/async-await                                                    | `std::future` + 线程池                        | MCP/LSP 各持独立 io 线程                                      |
| 配置读取       | `Config.get().mcp`                                                     | `Config::instance().get<T>("mcp.*")`          | 扩展 Config 路径 `"mcp"` / `"lsp"`                            |
| 事件发布       | `Bus.publish(ToolsChanged, {...})`                                     | `EventBus::instance().publish<T>(name, data)` | 对齐事件名称 `mcp.tools.changed`                              |
| OAuth 存储     | `~/.opencode/mcp-auth.json`                                            | `~/.turbot/mcp-auth.json`                     | 权限 `0600`                                                   |

### 1.3 OpenCode ACP 已知缺陷（Turbot 可超越）

OpenCode ACP README 明确标注以下为「Not Yet Implemented」：

1. **流式响应（Streaming Responses）**：当前返回完整响应，不发送 `session/update` 流式通知
2. **工具调用报告（Tool Call Reporting）**：不向 IDE 上报工具执行进度
3. **Session 模式切换（Session Modes）**：无 mode switching 支持
4. **认证（Authentication）**：无实际认证实现
5. **终端支持（Terminal Support）**：仅占位符
6. **Session 持久化（Session Persistence）**：`session/load` 未真正恢复对话历史

> **注意**：实际代码中 OpenCode `loadSession` 已部分实现历史回放（调用 `processMessage()`），但 README 仍标注为缺陷，说明实现仍不完整或未通过测试。

> **Turbot 优势**：Session 系统已有持久化、`messages()` API、fork 机制，可直接弥补缺陷 6；
> EventBus 可驱动流式推送，弥补缺陷 1、2；Mode/Model 配置已有基础。

```cpp
// libs/core/include/turbot/core/mcp/mcp.hpp
#pragma once
#include <turbot/core/common/export.hpp>
#include <nlohmann/json.hpp>
#include <string>
#include <vector>
#include <optional>
#include <functional>
#include <future>
#include <unordered_map>

namespace turbot::core::mcp {

/// MCP 连接状态（对齐 OpenCode MCP.Status discriminatedUnion）
enum class MCPStatus {
    Connected,
    Disabled,
    Failed,
    NeedsAuth,
    NeedsClientRegistration,
};

std::string mcp_status_to_string(MCPStatus status);

/// MCP 工具定义（对齐 MCP 协议 tools/list 响应）
struct TURBOT_CORE_API MCPTool {
    std::string name;
    std::string description;
    nlohmann::json input_schema;   // JSON Schema object，type 固定为 "object"

    [[nodiscard]] nlohmann::json to_json() const;
    static MCPTool from_json(const nlohmann::json& j);
};

/// MCP 资源（对齐 OpenCode MCP.Resource zod schema）
struct TURBOT_CORE_API MCPResource {
    std::string name;
    std::string uri;
    std::optional<std::string> description;
    std::optional<std::string> mime_type;
    std::string client;  // 所属 server 名称

    [[nodiscard]] nlohmann::json to_json() const;
    static MCPResource from_json(const nlohmann::json& j);
};

/// MCP 提示词模板
struct TURBOT_CORE_API MCPPrompt {
    std::string name;
    std::string description;
    std::vector<std::string> arguments;

    [[nodiscard]] nlohmann::json to_json() const;
    static MCPPrompt from_json(const nlohmann::json& j);
};

/// MCP 客户端配置（对齐 OpenCode Config.Mcp type）
struct TURBOT_CORE_API MCPClientConfig {
    std::string name;
    std::string type;  // "local" | "remote"

    // type=local
    std::vector<std::string> command;  // [cmd, ...args]
    std::unordered_map<std::string, std::string> environment;

    // type=remote
    std::optional<std::string> url;
    std::optional<nlohmann::json> oauth;  // false(json bool) | oauth-config-object
    std::optional<std::unordered_map<std::string, std::string>> headers;

    bool enabled = true;
    int timeout_ms = 30000;  // 对齐 OpenCode DEFAULT_TIMEOUT = 30_000
};

/// JSON-RPC 2.0 基础消息
struct JsonRpcRequest {
    std::string jsonrpc = "2.0";
    std::optional<int64_t> id;   // nullopt => notification
    std::string method;
    nlohmann::json params = nlohmann::json::object();
};

struct JsonRpcResponse {
    std::string jsonrpc = "2.0";
    int64_t id = 0;
    std::optional<nlohmann::json> result;
    std::optional<nlohmann::json> error;
    [[nodiscard]] bool is_error() const noexcept { return error.has_value(); }
};

/// 传输层抽象接口
class TURBOT_CORE_API ITransport {
public:
    virtual ~ITransport() = default;

    /// 连接（启动子进程或建立 HTTP 连接）
    virtual std::future<void> connect() = 0;

    /// 发送请求并等待响应
    virtual std::future<JsonRpcResponse> send_request(
        const std::string& method,
        const nlohmann::json& params = nlohmann::json::object()
    ) = 0;

    /// 发送通知（无响应，no-id request）
    virtual void send_notification(
        const std::string& method,
        const nlohmann::json& params = nlohmann::json::object()
    ) = 0;

    /// 注册服务器通知处理器（server-to-client）
    virtual void on_notification(
        const std::string& method,
        std::function<void(const nlohmann::json&)> handler
    ) = 0;

    /// 断开连接
    virtual std::future<void> close() = 0;

    /// 子进程 PID（仅 StdioTransport 返回有效值，其余返回 -1）
    virtual int pid() const noexcept { return -1; }
};

} // namespace turbot::core::mcp
```

#### 3.1.3 StdioTransport 设计要点

- `fork + execvp` 启动子进程，持有 stdin/stdout/stderr pipe fd
- 独立 io 读线程：持续从 stdout 读取 newline-delimited JSON，按 `id` 派发到 pending `promise`
- 通知消息（无 `id` 字段）：调用对应 `on_notification` 处理器
- stderr 异步日志（对齐 OpenCode `transport.stderr?.on("data", ...)`）
- 进程退出时清理所有 pending futures（以 error response 完成）
- `pid()` 供 `MCPManager` 清理孙进程（对齐 OpenCode `descendants(pid)` + SIGTERM 逻辑）

#### 3.1.4 HttpTransport / SSETransport 设计要点

- `HttpTransport`：先尝试 POST `{url}` 发送 JSON-RPC 请求（StreamableHTTP 模式）；若失败则降级到 SSETransport（对齐 OpenCode 先尝试 `StreamableHTTPClientTransport` 再尝试 `SSEClientTransport`）
- `SSETransport`：建立 SSE 长连接，通过 `HttpClient::request_stream()` 接收推送消息；请求通过独立 POST 发出
- OAuth 状态：传输层持有 `auth_provider` 引用，连接时触发 OAuth 流程并抛出 `UnauthorizedError`

#### 3.1.5 验收标准

- `StdioTransport` 能启动 `npx -y @playwright/mcp` 并收到 JSON-RPC initialize 响应
- `HttpTransport` 先尝试 StreamableHTTP，降级到 SSE（对齐 OpenCode fallback 逻辑）
- 单元测试覆盖率 ≥ 80%

```cpp
#pragma once
#include <turbot/core/mcp/mcp.hpp>

namespace turbot::core::mcp {

/// MCP 协议客户端（封装传输层，实现 MCP initialize 握手和工具/资源/提示词 API）
class TURBOT_CORE_API MCPClient {
public:
    explicit MCPClient(std::unique_ptr<ITransport> transport);
    ~MCPClient();

    /// 建立连接并完成 MCP initialize 握手
    std::future<MCPStatus> connect(
        const std::string& client_name,  // 应用名（"turbot"）
        const std::string& version       // 版本（"1.0.0"）
    );

    /// 断开并终止子进程
    std::future<void> close();

    [[nodiscard]] MCPStatus status() const noexcept;

    std::future<std::vector<MCPTool>>     list_tools();
    std::future<nlohmann::json>           call_tool(
        const std::string& name,
        const nlohmann::json& args,
        int timeout_ms = 30000  // 对齐 OpenCode DEFAULT_TIMEOUT；resetTimeoutOnProgress = true
    );
    std::future<std::vector<MCPResource>> list_resources();
    std::future<nlohmann::json>           read_resource(const std::string& uri);
    std::future<std::vector<MCPPrompt>>   list_prompts();
    std::future<std::string>              get_prompt(
        const std::string& name,
        const nlohmann::json& args = nlohmann::json::object()
    );

    /// 注册 tools/list_changed 通知处理器（对齐 OpenCode registerNotificationHandlers）
    void on_tools_changed(std::function<void()> callback);

    /// 获取子进程 PID（用于孙进程清理）
    [[nodiscard]] int pid() const noexcept;

private:
    std::unique_ptr<ITransport> transport_;
    MCPStatus status_ = MCPStatus::Disabled;
    std::atomic<int64_t> next_id_{1};
    mutable std::mutex mutex_;
};

} // namespace turbot::core::mcp


// libs/core/include/turbot/core/mcp/manager.hpp
#pragma once
#include <turbot/core/mcp/mcp.hpp>
#include <turbot/core/mcp/client.hpp>

namespace turbot::core::mcp {

/// MCP 管理器——单例，管理所有 MCP 服务器连接生命周期
class TURBOT_CORE_API MCPManager {
public:
    static MCPManager& instance();
    MCPManager(const MCPManager&) = delete;
    MCPManager& operator=(const MCPManager&) = delete;

    /// 从配置列表初始化所有 MCP 服务器（App 启动时调用）
    void initialize(const std::vector<MCPClientConfig>& configs);

    /// 添加/重连单个服务器（对齐 OpenCode MCP.add()）
    std::future<MCPStatus> add(const std::string& name, const MCPClientConfig& config);

    /// 显式连接（enabled=true 覆盖，对齐 OpenCode MCP.connect()）
    std::future<void> connect(const std::string& name);

    /// 断开服务器（标记为 disabled，对齐 OpenCode MCP.disconnect()）
    std::future<void> disconnect(const std::string& name);

    /// 移除服务器（含关闭连接）
    void remove(const std::string& name);

    /// 查询所有服务器状态（对齐 OpenCode MCP.status()）
    [[nodiscard]] std::unordered_map<std::string, MCPStatus> status() const;

    /// 获取所有已连接工具（对齐 OpenCode MCP.tools()）
    /// 命名规则（对齐 OpenCode）：
    ///   sanitized_client + "_" + sanitized_tool
    ///   其中 sanitize = replace(/[^a-zA-Z0-9_-]/g, "_")
    std::future<std::unordered_map<std::string, nlohmann::json>> tools();

    /// 将工具注册到 ToolRegistry
    std::future<void> sync_tools_to_registry();

    /// 获取所有资源（对齐 OpenCode MCP.resources()）
    std::future<std::vector<MCPResource>> all_resources();

    /// 获取所有提示词（对齐 OpenCode MCP.prompts()，键格式 "client:prompt"）
    std::future<std::unordered_map<std::string, MCPPrompt>> all_prompts();

    /// OAuth 认证支持
    std::future<std::string> start_auth(const std::string& name);     // 返回 authorizationUrl
    std::future<MCPStatus>   authenticate(const std::string& name);   // 打开浏览器+等待回调
    std::future<MCPStatus>   finish_auth(const std::string& name, const std::string& code);
    std::future<void>        remove_auth(const std::string& name);
    bool                     supports_oauth(const std::string& name) const;

    /// 关闭所有连接，并发送 SIGTERM 给孙进程树（对齐 OpenCode 清理逻辑）
    void shutdown();
```

#### 3.3.3 OAuth 完整流程（对齐 OpenCode `startAuth`/`authenticate`/`finishAuth`）

1. **`start_auth(mcp_name)`**（对齐 `MCP.startAuth`）：
   - 确保 OAuth callback 服务器已启动（Turbot 使用本地 HTTP 服务器监听回调）
   - 生成 `oauthState`（32字节随机十六进制），调用 `McpAuth::update_oauth_state()` 存储
   - 构造 `McpOAuthProvider`，创建 `StreamableHTTPClientTransport` 尝试连接
   - 捕获 `UnauthorizedError`，返回 `capturedUrl`（authorization URL）
   - 存储 pending transport（供 `finish_auth` 使用）

2. **`authenticate(mcp_name)`**（对齐 `MCP.authenticate`）：
   - 调用 `start_auth` 获取 URL
   - 注册 callback 等待（**先注册，再开浏览器**，对齐 OpenCode 防竞争条件）
   - 尝试打开浏览器；失败时发布 `EventBus "mcp.browser.open.failed"` 通知（对齐 OpenCode `MCP.BrowserOpenFailed`）
   - 等待 callback 收到 `code`
   - 校验 `oauthState`，调用 `McpAuth::clear_oauth_state()`
   - 调用 `finish_auth(mcp_name, code)`

3. **`finish_auth(mcp_name, code)`**（对齐 `MCP.finishAuth`）：
   - 用 code 交换 token（调用 pending transport 的 finishAuth）
   - 清除 code_verifier（`McpAuth::clear_code_verifier`）
   - 删除 pending transport
   - 重连 MCP 服务器（`MCPManager::add`）

#### 3.3.4 验收标准

- `McpAuth::get_for_url()` 在 server_url 变更时返回 `nullopt`；无 serverUrl 字段也返回 `nullopt`
- `is_token_expired()` 返回三态：`nullopt`（无 token）、`false`（未过期）、`true`（已过期）
- Token 以 `0600` 权限写入 `~/.turbot/mcp-auth.json`
- 浏览器打开失败时 EventBus 发布 `"mcp.browser.open.failed"` 事件

```cpp
/// LSP 服务器进程句柄（对齐 OpenCode LSPServer.Handle）
struct ServerHandle {
    int pid = -1;
    int stdin_fd  = -1;
    int stdout_fd = -1;
    nlohmann::json initialization;  // workspace/configuration 响应内容（可为 null）
};

/// LSP JSON-RPC 客户端（工厂模式，对齐 OpenCode LSPClient.create()）
class TURBOT_CORE_API LSPClient {
public:
    /// 工厂方法：发送 initialize → initialized，注册通知处理器，返回就绪客户端
    static std::unique_ptr<LSPClient> create(

    // open 逻辑：
    //   首次打开 → workspace/didChangeWatchedFiles(Created) + textDocument/didOpen
    //   再次打开 → workspace/didChangeWatchedFiles(Changed) + textDocument/didChange
    void notify_open(const std::string& path);   // 读取文件内容并发送
    void notify_close(const std::string& path);
    void notify_change(const std::string& path, const std::string& content);

    // ── 诊断（debounce 150ms，超时 3000ms，对齐 OpenCode DIAGNOSTICS_DEBOUNCE_MS 和 withTimeout）──
    std::future<void> wait_for_diagnostics(const std::string& path);
    [[nodiscard]] const std::unordered_map<std::string, std::vector<Diagnostic>>&
        diagnostics() const noexcept;

    // ── LSP 请求 ─────────────────────────────────────────────────────
    std::future<std::optional<Hover>>             hover(const std::string& uri, Position pos);
    std::future<std::vector<Location>>            definition(const std::string& uri, Position pos);
    std::future<std::vector<Location>>            references(const std::string& uri, Position pos);
    std::future<std::vector<Location>>            implementation(const std::string& uri, Position pos);
    std::future<std::vector<Symbol>>              workspace_symbol(const std::string& query);
    std::future<std::vector<DocumentSymbol>>      document_symbol(const std::string& uri);

    // ── 调用层级（对齐 OpenCode prepareCallHierarchy/incomingCalls/outgoingCalls）──

    std::future<std::vector<nlohmann::json>>      incoming_calls(const nlohmann::json& item);
    std::future<std::vector<nlohmann::json>>      outgoing_calls(const nlohmann::json& item);

private:
    LSPClient() = default;
    struct Impl;
    std::unique_ptr<Impl> impl_;
};
```

#### 3.5.3 实现要点

- **Content-Length framing**：LSP 消息格式 `"Content-Length: N\r\n\r\n{json}"`，独立读线程解析
- **initialize 握手**：
  - 发送 `initialize`（含 `rootUri`, `processId`, `workspaceFolders`, `initializationOptions`, `capabilities`）
  - 收到响应后发送 `initialized` 通知
  - 若 `server.initialization != null`，发送 `workspace/didChangeConfiguration`（对齐 OpenCode `if (input.server.initialization)`）
- **initialize 超时**：45000ms（对齐 OpenCode `withTimeout(..., 45_000)`）
- **服务器回调处理**（完整对齐 OpenCode client.ts）：
  - `textDocument/publishDiagnostics` → 更新 diagnostics map，debounce 150ms 后发布 EventBus 事件
    - 特殊规则：typescript 服务器首次接收不触发（对齐 `if (!exists && serverID === "typescript") return`）
  - `window/workDoneProgress/create` → 返回 null（日志记录）
  - `workspace/configuration` → 返回 `[handle.initialization ?? {}]`
  - `client/registerCapability` / `client/unregisterCapability` → 返回 null（acknowledge）
  - `workspace/workspaceFolders` → 返回 `[{name:"workspace", uri: rootUri}]`
- **EventBus 事件**：
  - `"lsp.client.diagnostics"`：payload `{server_id, path}`（对齐 OpenCode `LSPClient.Event.Diagnostics`）

#### 3.5.4 验收标准

- 对 clangd 发起 `textDocument/hover`，在 5s 内收到有效响应
- `publishDiagnostics` 通知正确更新 diagnostics map，并 debounce 150ms 后触发 EventBus
- `waitForDiagnostics` 在 3000ms 超时后安静返回（不抛异常，对齐 OpenCode `.catch(() => {})`）
- 单元测试使用 mock ServerHandle 验证 Content-Length framing 解析

#### 3.9.3 TurbotACPAgent 实现要点

- **`initialize`**（对齐 OpenCode `Agent.initialize`）：
  - 检查 `req.client_capabilities._meta["terminal-auth"]` 是否为 true（对齐 OpenCode 能力协商）
  - 返回 `agentCapabilities`（含 `loadSession`、`mcpCapabilities`、`promptCapabilities`、`sessionCapabilities`）
  - 返回 `authMethods`（turbot login 方式）
  - 返回 `agentInfo`（name: "Turbot", version）

- **`new_session`**（对齐 OpenCode `Agent.newSession`）：
  - 调用 `Session::create({directory, ...})`，创建 Turbot Session
  - 动态加载 MCP 服务器（`MCPManager::add()`）
  - 解析可用 modes（Turbot Agent 列表）和 models（Provider 列表，含 variants）
  - 异步推送 `available_commands_update`（对齐 OpenCode setTimeout 0 推送）

- **`load_session`**（弥补 OpenCode 缺陷6 - Session Persistence，完整实现）：
  - 调用 `Session::get(session_id)` 验证 Session 存在
  - 调用 `Session::messages()` 获取历史消息，调用 `process_message()` 逐条回放到 ACP 客户端
  - 从最后一条 user 消息提取 model/mode 信息（对齐 OpenCode `loadSession` 实现）
  - 推送 `usage_update`

- **`resume_session`**（对齐 OpenCode `unstable_resumeSession`）：
  - 轻量恢复，不回放历史，仅同步状态和 `usage_update`

- **`list_sessions`**（对齐 OpenCode `unstable_listSessions`）：
  - 调用 `Session::list({roots: true})`，按 `time.updated` 降序排序
  - 分页（limit=100），支持 `cursor`（Unix timestamp）
  - 返回 `sessions` 数组和 `nextCursor`

- **`prompt`**（弥补 OpenCode 缺陷1/2 - Streaming/Tool Reporting）：
  - 支持 `/` 命令前缀（`/compact` → `Session::summarize`，其他命令查 CommandRegistry）
  - 订阅 EventBus session 事件驱动 `on_update` 回调
  - 完成后调用 `send_usage_update()`

- **`cancel`**：调用 `Session::abort(session_id)`（对齐 OpenCode `sdk.session.abort()`）

- **`fork_session`**（对齐 OpenCode `unstable_forkSession`）：
  - 调用 `Session::fork({parent_id})`
  - 历史回放（`process_message()`），推送 `usage_update`

- **`set_mode`**（弥补 OpenCode 缺陷3 - Session Modes）：
  - 验证 mode 在可用 Agents 列表中存在
  - 更新 `ACPSessionManager::set_mode()`

- **`process_message()`**（对齐 OpenCode `processMessage` 私有方法）：
  - 处理 `text` part → `user_message_chunk` / `agent_message_chunk`
  - 处理 `tool` part → `tool_call` (pending) + `tool_call_update` (in_progress/completed/error)
  - 处理 `file` part → `resource_link`（file:// URL）/ `image` / `resource` block
  - 处理 `reasoning` part → `agent_thought_chunk`
  - 处理 `todowrite` 工具输出 → 额外发送 `plan` 类型更新

#### 3.9.4 验收标准

- `session/new` → `session/prompt` E2E 测试通过，能收到 AI 响应
- `session/load` 后 ACP 客户端收到历史消息回放（`agent_message_chunk`/`tool_call_update`）
- `prompt` 执行期间 `on_update` 收到流式 `agent_message_chunk` 通知
- `session/fork` 创建独立 Session，并回放历史到 ACP 客户端

#### 3.10.1 `session/update` 通知完整类型（对齐 OpenCode agent.ts 实际实现）

OpenCode agent.ts 实际发送的 `sessionUpdate` 类型（基于源码完整分析，共 **7 种类型**）：

```json
// ──── 类型1：文本 chunk（message.part.delta 事件，type=text field=text，ignored != true）
{
  "jsonrpc": "2.0", "method": "session/update",
  "params": {
    "sessionId": "...",
    "update": {
      "sessionUpdate": "agent_message_chunk",
      "content": { "type": "text", "text": "...chunk..." }
    }
  }
}

// ──── 类型2：用户消息 chunk（历史回放中 role=user 的文本 part）
{
  "sessionUpdate": "user_message_chunk",
  "content": {
    "type": "text", "text": "...",
    "annotations": { "audience": ["user"] }   // synthetic/ignored 附加标注
  }
}

// ──── 类型3：推理 chunk（message.part.delta 中 type=reasoning field=text）
{
  "sessionUpdate": "agent_thought_chunk",
  "content": { "type": "text", "text": "...reasoning delta..." }
}

// ──── 类型4：工具初始 pending（toolStart，每个 callID 只发送一次）
{
  "sessionUpdate": "tool_call",
  "toolCallId": "...",
  "title": "bash",
  "kind": "execute",
  "status": "pending",
  "locations": [],
  "rawInput": {}
}

// ──── 类型5：工具状态更新（message.part.updated，4种 status）
{
  "sessionUpdate": "tool_call_update",
  "toolCallId": "...",
  "status": "in_progress" | "completed" | "failed",
  "kind": "read" | "write" | "edit" | "execute" | "fetch" | "search" | "other",
  "title": "...",
  "locations": [{"path": "/abs/path"}],
  "rawInput": {...},
  // completed 时附加：
  "rawOutput": { "output": "...", "metadata": {...} },
  "content": [
    { "type": "content", "content": { "type": "text", "text": "..." } },
    // edit 工具时额外附加 diff block：
    { "type": "diff", "path": "...", "oldText": "...", "newText": "..." }
  ]
}

// ──── 类型6：用量统计（prompt 完成后异步发送）
{
  "sessionUpdate": "usage_update",
  "used": 1234,        // input_tokens + cache_read_tokens
  "size": 200000,      // 模型上下文窗口大小
  "cost": { "amount": 0.01, "currency": "USD" }
}

// ──── 类型7：TODO 计划（todowrite 工具完成时额外发送）
{
  "sessionUpdate": "plan",
  "entries": [{ "priority": "medium", "status": "in_progress" | "completed" | "pending", "content": "..." }]
}

// ──── 类型8：可用命令更新（session 创建/加载后异步发送，setTimeout 0）
{
  "sessionUpdate": "available_commands_update",
  "availableCommands": [
    { "name": "compact", "description": "compact the session" },
    ...
  ]
}
```

**ToolKind 映射**（对齐 OpenCode `toToolKind` 函数）：

| 工具名                       | Kind      |
| ---------------------------- | --------- |
| `bash`                       | `execute` |
| `webfetch`                   | `fetch`   |
| `edit`, `patch`, `write`     | `edit`    |
| `grep`, `glob`, `context7_*` | `search`  |
| `list`, `read`               | `read`    |
| 其他（MCP 工具等）           | `other`   |

> Turbot 实现优先支持类型 1-7（弥补 OpenCode 缺陷1、2），类型8（available_commands_update）可后续实现。

```cpp
// 环境变量：TURBOT_ENABLE_QUESTION_TOOL=1 启用 QuestionTool
```

**Zed 集成配置**（`~/.config/zed/settings.json`）：

```json
{
  "agent_servers": {
    "Turbot": {
      "command": "turbot",
      "args": ["acp"]
    }
  }
}
```

#### 3.10.3 验收标准

- `turbot acp` 启动后响应 `initialize` 请求，返回含 `agentCapabilities` 的 `InitializeResponse`
- `session/prompt` 执行期间持续推送 `session/update` 通知（`agent_message_chunk`）
- 工具执行时推送 `tool_call` (pending) → `tool_call_update` (in_progress/completed/failed)
- `todowrite` 工具完成时推送 `plan` 通知
- SIGTERM 触发优雅关闭（等待当前 prompt 完成）

## 八、风险与依赖

### 8.1 技术风险

| 风险                                     | 影响       | 缓解措施                                                      |
| ---------------------------------------- | ---------- | ------------------------------------------------------------- |
| MCP 协议版本演进（当前 2024-11-05）      | API 变化   | 仅实现核心子集（Tools/Resources/Prompts），隔离传输层便于升级 |
| LSP 服务器安装环境差异                   | 功能降级   | 服务器未安装时标记 broken 跳过，不影响其他功能                |
| ACP 协议稳定性（v1 尚在演进）            | 接口变化   | 隔离 JSON-RPC dispatcher，协议变更只需修改分发表              |
| C++ 无官方 MCP/ACP SDK                   | 实现成本高 | 基于已有 `HttpClient`（SSE）+ subprocess pipe 手工实现        |
| `session/update` 事件格式随 ACP SDK 演进 | 兼容性     | 封装为独立 `session_update_builder`，易于替换                 |
| ACP permission 系统实现复杂度            | 实现难度高 | 对齐 OpenCode `permission.asked` 事件+队列模式，逐步实现      |
