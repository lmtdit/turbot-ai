## 目标

基于 subprocess pipe + Content-Length framing 实现 LSP JSON-RPC 客户端，对齐 OpenCode `lsp/client.ts`（使用 `vscode-jsonrpc`）。关键行为：诊断 debounce 150ms；`wait_for_diagnostics` 超时 3000ms；TypeScript 服务器首次诊断特殊规则；initialize 超时 45000ms。

### 步骤 2：定义 LSPClient 接口（client.hpp）

```cpp
struct ServerHandle {
    int pid = -1;
    int stdin_fd  = -1;
    int stdout_fd = -1;
    nlohmann::json initialization;  // workspace/configuration 响应内容（null = 不发送）
};

class LSPClient {
public:
    // 工厂方法：发送 initialize + initialized，注册通知处理器，返回就绪客户端
    static std::unique_ptr<LSPClient> create(
        const std::string& server_id,
        const ServerHandle& handle,
        const std::string& root    // workspace root（绝对路径）
    );

    ~LSPClient();

    [[nodiscard]] const std::string& server_id() const noexcept;
    [[nodiscard]] const std::string& root() const noexcept;

    void shutdown();  // 发送 shutdown + exit 通知，关闭 fd，kill 进程

    // ── 文件通知 ─────────────────────────────────────────────────────────
    // 首次打开：workspace/didChangeWatchedFiles(Created) + textDocument/didOpen
    // 再次打开：workspace/didChangeWatchedFiles(Changed) + textDocument/didChange
    // 并删除旧诊断（对齐 OpenCode `diagnostics.delete(input.path)`）
    void notify_open(const std::string& path);
    void notify_close(const std::string& path);
    void notify_change(const std::string& path, const std::string& content);

    // ── 诊断（debounce 150ms，超时 3000ms）─────────────────────────────────
    std::future<void> wait_for_diagnostics(const std::string& path);
    [[nodiscard]] const std::unordered_map<std::string, std::vector<Diagnostic>>&
        diagnostics() const noexcept;

    // ── LSP 请求 ─────────────────────────────────────────────────────────
    std::future<std::optional<Hover>>             hover(const std::string& uri, Position pos);
    std::future<std::vector<Location>>            definition(const std::string& uri, Position pos);
    std::future<std::vector<Location>>            references(const std::string& uri, Position pos);
    std::future<std::vector<Location>>            implementation(const std::string& uri, Position pos);
    std::future<std::vector<Symbol>>              workspace_symbol(const std::string& query);
    std::future<std::vector<DocumentSymbol>>      document_symbol(const std::string& uri);

    // ── 调用层级 ─────────────────────────────────────────────────────────
    std::future<std::vector<nlohmann::json>>      prepare_call_hierarchy(const std::string& uri, Position pos);
    std::future<std::vector<nlohmann::json>>      incoming_calls(const nlohmann::json& item);
    std::future<std::vector<nlohmann::json>>      outgoing_calls(const nlohmann::json& item);

private:
    LSPClient() = default;
    struct Impl;
    std::unique_ptr<Impl> impl_;
};
```

### 步骤 3：实现 LSPClient（client.cpp）

#### Content-Length Framing（核心实现）

**读取格式**：

```
Content-Length: 123\r\n
\r\n
{"jsonrpc":"2.0","id":1,"result":{...}}
```

**读线程实现要点**：

```
loop:
  read line until \r\n → 解析 Content-Length: N
  read \r\n（空行分隔符）
  read 精确 N 字节 → JSON 解析
  → is response (has "id") → 按 id 分发到 pending promise
  → is notification (method, no "id") → 调用对应 handler
  → is request (method, has "id") → 调用 request handler（workspace/configuration 等）
```

**写入格式**：

```cpp
std::string body = json.dump();
std::string msg = "Content-Length: " + std::to_string(body.size()) + "\r\n\r\n" + body;
write(stdin_fd_, msg.data(), msg.size());
```

#### initialize 握手

**发送请求**（initialize 超时 45000ms，对齐 OpenCode `withTimeout(..., 45_000)`）：

```json
{
  "method": "initialize",
  "params": {
    "rootUri": "file:///path/to/workspace",
    "processId": <PID>,
    "workspaceFolders": [{"uri": "file:///path/to/workspace", "name": "workspace"}],
    "capabilities": {
      "window": { "workDoneProgress": true },
      "workspace": {
        "configuration": true,
        "didChangeWatchedFiles": { "dynamicRegistration": true }
      },
      "textDocument": {
        "synchronization": { "didOpen": true, "didChange": true },
        "publishDiagnostics": { "versionSupport": true }
      }
    }
  }
}
```

**握手流程**：

1. 发送 `initialize`（超时 45s）
2. 收到响应后发送 `initialized` 通知（无参数）
3. 若 `handle.initialization != null`，发送 `workspace/didChangeConfiguration`（对齐 OpenCode）
4. 握手失败（超时/error）→ 工厂方法返回 nullptr

#### 服务器通知处理器

完整对齐 OpenCode `lsp/client.ts` 注册的所有处理器：

| 通知方法                            | 处理逻辑                                                                                                                     |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `textDocument/publishDiagnostics`   | **先** `diagnostics_[uri] = params`；**再**检查 `!exists && typescript` 则跳过 debounce；否则 debounce 150ms 后发布 EventBus |
| `window/workDoneProgress/create`    | 返回 null（仅记录 debug 日志）                                                                                               |
| `workspace/configuration` (request) | 返回 `[handle.initialization ?? {}]`                                                                                         |
| `client/registerCapability`         | 返回 null（acknowledge）                                                                                                     |
| `client/unregisterCapability`       | 返回 null（acknowledge）                                                                                                     |
| `workspace/workspaceFolders`        | 返回 `[{name: "workspace", uri: rootUri}]`                                                                                   |

**TypeScript 服务器特殊规则**（对齐 OpenCode `if (!exists && input.serverID === "typescript") return`）：

```cpp
// publishDiagnostics 处理器中（严格对齐 OpenCode 顺序）：
// 先更新 diagnostics_ map，再判断 TypeScript 规则
bool exists = diagnostics_.count(uri) > 0;  // 更新前记录是否存在
diagnostics_[uri] = params["diagnostics"];   // 先更新（必须在判断之前）
if (!exists && server_id_ == "typescript") {
    // 首次收到 TypeScript 服务器的诊断，跳过（不触发 debounce）
    // 注意：不需要额外创建空条目，上面已经更新了
    return;
}
// 触发 debounce
```

#### Debounce 150ms 实现

```cpp
// DIAGNOSTICS_DEBOUNCE_MS = 150（对齐 OpenCode）
// 使用 condition_variable + 计时器线程实现 debounce
// 每次收到 publishDiagnostics 时重置计时器
// 150ms 内无新诊断 → 触发 EventBus 发布

struct DebounceState {
    std::mutex mutex;
    std::condition_variable cv;
    bool dirty = false;
    std::thread timer_thread;
};
```

#### wait_for_diagnostics 超时 3000ms

```cpp
std::future<void> LSPClient::wait_for_diagnostics(const std::string& path) {
    return std::async(std::launch::async, [this, path]() {
        // 等待对应 path 的 diagnostics 更新事件
        // 超时 3000ms 后静默返回（不抛异常，对齐 OpenCode .catch(() => {})）
        auto deadline = std::chrono::steady_clock::now() + std::chrono::milliseconds(3000);
        std::unique_lock<std::mutex> lock(diag_mutex_);
        diag_cv_.wait_until(lock, deadline, [&] {
            return diag_updated_for_.count(path) > 0;
        });
        // 超时静默返回
    });
}
```
