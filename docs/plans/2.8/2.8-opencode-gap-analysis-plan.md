## 一、架构对比总览

### 1.1 核心流程对比

| 维度               | OpenCode                                                                   | Turbot 2.x                                                         | 差距                                                         |
| ------------------ | -------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------ |
| **主循环入口**     | `SessionPrompt.command()` → `SessionProcessor.process()` while 循环        | `SessionLoop::run()` → `step()` while 循环                         | 结构对等，Turbot 封装更清晰                                  |
| **流式处理**       | `LLM.stream()` → AI SDK `streamText` fullStream 逐事件 for-await           | `LLM::stream()` → `Provider::chat_stream()` SSE + `StreamingState` | Turbot 缺少 AI SDK 的 `experimental_repairToolCall` 容错修复 |
| **工具调用**       | 工具内嵌在 AI SDK `tool()` 对象，`toolChoice` 支持 auto/required/none      | `ToolRegistry` + `ToolContext`，手动调用 `execute()`               | Turbot 缺 `toolChoice` 控制 + LiteLLM 兼容 noop tool         |
| **重试机制**       | `SessionRetry` 在 `processor.ts` catch 块内循环重试，完全集成              | `RetryManager` 已实现但**未集成**到 `session_loop.cpp`             | **关键差距 P0**                                              |
| **压缩触发**       | `finish-step` 事件内判断 `isOverflow` → `needsCompaction = true`           | `needs_compaction()` 在 `step()` 入口检查 `token_count_`           | Turbot 缺 per-step token 精确统计（用估算值）                |
| **上下文剪枝**     | `SessionCompaction.prune()` — 保护最近 40K tokens 工具输出，丢弃旧工具结果 | 无 prune 机制                                                      | **差距 P1**                                                  |
| **Snapshot 实现**  | 基于 `git write-tree / checkout`（独立 git 仓库）                          | 基于内存 SHA-256 哈希 + 文件内容缓存（50MB 上限）                  | 两种策略各有优劣，Turbot 无法利用 git history                |
| **Revert（撤销）** | `SessionRevert.revert()` 精确到 Part 粒度，还原文件 + 截断消息历史         | 无                                                                 | **差距 P1**                                                  |
| **SessionStatus**  | `SessionStatus`：idle / busy / retry（含下次重试时间）→ Bus 广播           | 无独立状态系统，只有 `running_` 原子标志                           | **差距 P1**                                                  |
| **Bus 事件系统**   | 全局 `Bus.publish/subscribe` 解耦所有模块，UI 通过 SSE 订阅                | 6 个回调函数硬绑定到 SessionLoop                                   | **架构差距 P1**                                              |
| **会话分享**       | `Session.share()` 生成公开 URL（ShareNext），自动分享选项                  | 无                                                                 | **差距 P3**                                                  |
| **Worktree 支持**  | `Session.Info.workspaceID`，多 worktree 隔离                               | 无                                                                 | **差距 P3**                                                  |
| **Plugin 系统**    | `Plugin.trigger("chat.params", ...)` 可在 LLM 调用前后注入逻辑             | 无                                                                 | **差距 P2**                                                  |
| **OpenTelemetry**  | `experimental_telemetry`，集成 OTEL trace                                  | 无                                                                 | **差距 P3**                                                  |

## 二、端到端串联评估

### 2.1 当前 Turbot 端到端路径

```
用户输入
  → SessionLoop::run()
      → process_user_message()       ✅
      → step() loop
          → needs_compaction()        ✅（token 估算，非精确）
          → process_llm_response()
              → build_llm_messages()  ✅
              → LLM::stream()         ✅（无 repairToolCall）
              ↓ 错误时：
              → on_error_ 回调        ⚠️ 无自动重试
              ↓ 有 tool_calls：
              → execute_tool()        ✅（有 try-catch）
              → 死循环检测            ✅（doom_loop_threshold）
  → 回调通知 UI                      ⚠️ 硬绑定回调，无 Bus
```

### 2.2 断裂点分析

| 断裂点                      | 影响                               | 严重度 |
| --------------------------- | ---------------------------------- | ------ |
| LLM 调用无自动重试          | 429/503 错误直接暴露给调用方       | P0     |
| token 用估算不精确          | 压缩触发时机不准确，可能过早或过晚 | P0     |
| 无 SessionStatus 广播       | UI/调用方无法感知 retry 等待状态   | P1     |
| 无 Revert                   | 用户无法撤销错误的文件修改         | P1     |
| 无 Bus                      | 多模块解耦困难，扩展性受限         | P1     |
| 工具调用时无 permission ask | 权限系统框架完整但 ask 流程未实现  | P1     |

### 2.8.1 RetryManager → SessionLoop 集成

**目标**：LLM 调用失败时自动重试（429/503），与 opencode `SessionRetry` 行为对齐。

**验收标准**：

- [ ] `SessionLoop::process_llm_response()` 中 LLM 调用包裹 `RetryManager::with_retry()`
- [ ] 可重试错误（429/500/502/503/504）触发最多 5 次指数退避重试
- [ ] `RetryConfig` 默认值：`RETRY_INITIAL_DELAY=2000ms`，`RETRY_BACKOFF_FACTOR=2`，无 headers 时 `RETRY_MAX_DELAY_NO_HEADERS=30s`，有 `Retry-After` 头时上限为 max int32
- [ ] `Retry-After-Ms` / `Retry-After` 响应头优先于计算值（支持秒数和 HTTP date 格式）
- [ ] 重试期间触发 `on_error_` 回调携带 retry 状态（attempt/delay）
- [ ] abort*flag* 检查：abort 期间立即停止重试
- [ ] 单元测试：可重试错误 → 成功（第 3 次）；不可重试错误 → 立即失败

**实现要点**：

```cpp
// session_loop.cpp: process_llm_response()
auto result = RetryManager::with_retry(
    [&]() {
        return LLM::stream(*provider_, model_id_, params, handler);
    },
    config,
    [&](int attempt, const APIError& err, int delay_ms) {
        if (on_error_) on_error_(err.what(), "retry");
        // 未来：触发 SessionStatus retry 事件
    }
);
```

**涉及文件**：

- `libs/core/src/session/session_loop.cpp` — 主修改点
- `libs/core/include/turbot/core/session/session_loop.hpp` — 可能添加 retry 配置字段
- `tests/unit/session_loop_test.cpp` — 新增 retry 测试用例

### 2.8.3 Bus 事件系统

**目标**：引入发布/订阅 Bus，替换 SessionLoop 中的 6 个硬绑定回调函数。

**核心设计**（参照 opencode `Bus` 但改为 C++ 同步版本）：

```cpp
// turbot/core/bus/bus.hpp
namespace turbot::core::bus {

// 事件定义宏
struct MessageEvent { core::Message message; };
struct ToolCallEvent { string session_id; string tool_name; string call_id; nlohmann::json input; };
struct ToolResultEvent { string session_id; string tool_name; string call_id; tool::ToolResult result; };
struct StreamEvent { string session_id; core::StreamEvent event; };
struct StepEvent { string session_id; session::StepInfo info; };
struct ErrorEvent { string session_id; string error; string code; };

class Bus {
public:
    static Bus& instance();

    template<typename Event>
    void publish(const Event& event);

    template<typename Event>
    std::function<void()> subscribe(std::function<void(const Event&)> handler);

    template<typename Event>
    void unsubscribe_all();
};
}
```

**验收标准**：

- [ ] `Bus` 单例实现，支持类型安全的 publish/subscribe（用 `std::type_index` 区分事件类型）
- [ ] `SessionLoop` 的 6 个 `on_xxx_` 回调改为 `Bus::publish` 调用
- [ ] 旧 `set_on_message()` 等接口保留但内部转为 Bus 订阅（向后兼容）
- [ ] `Bus` 支持每个事件类型多订阅者
- [ ] 线程安全：`shared_mutex` 保护订阅者列表
- [ ] 单元测试：publish → 所有 subscriber 收到正确事件

**涉及文件**：

- `libs/core/include/turbot/core/bus/bus.hpp` — 新建
- `libs/core/src/bus/bus.cpp` — 新建
- `libs/core/include/turbot/core/bus/bus_event.hpp` — 新建（事件类型定义）
- `libs/core/src/session/session_loop.cpp` — 回调改 Bus

### 2.8.4 SessionStatus 广播

**目标**：SessionLoop 运行期间通过 Bus 广播 idle/busy/retry 状态。

**状态机**：

```
idle → busy（run() 开始）
busy → retry（LLM 调用失败可重试）
retry → busy（重试后继续）
busy → idle（run() 完成/中止）
```

**验收标准**：

- [ ] 新增 `SessionStatusEvent { string session_id; enum Status{Idle,Busy,Retry} status; int retry_attempt; string retry_message; int64_t retry_next_ms; }`
- [ ] `run()` 开始时发布 `Busy`，结束时发布 `Idle`
- [ ] retry 等待期间发布 `Retry`（含 attempt 和下次时间）
- [ ] Bus 订阅者可获取当前 session 状态
- [ ] 依赖 2.8.3（Bus 系统）

**涉及文件**：

- `libs/core/include/turbot/core/bus/bus_event.hpp` — 添加 SessionStatusEvent
- `libs/core/src/session/session_loop.cpp` — run() / retry 处发布状态

### 2.8.5 SessionRevert（撤销功能）

**目标**：允许用户撤销指定 Message 或 Part 之后的所有操作，并回滚文件变更。

**核心流程**（参照 opencode `SessionRevert`）：

```
revert(session_id, message_id, part_id?)
  ├─ 收集 message_id 之后的所有 PatchResult（文件变更）
  ├─ SnapshotManager::rollback_patch() 逐个回滚文件
  ├─ 从 DB 删除 message_id 及之后的消息
  └─ 记录 revert 信息到 Session（含回滚前 snapshot_id）

unrevert(session_id)
  ├─ SnapshotManager::apply_patch() 重新应用文件
  └─ 清除 revert 标记
```

**验收标准**：

- [ ] `SessionInfo` 增加 `revert` 字段：`{ message_id, part_id?, snapshot?, diff? }`
  - `snapshot`：revert 前拍摄的快照 ID（首次 revert 时记录，unrevert 时恢复）
  - `diff`：revert 范围内的 git diff 文本（用于 UI 展示变更摘要）
- [ ] `Session::revert(params)` 实现文件回滚 + 消息截断
- [ ] `Session::unrevert(session_id)` 重新应用变更
- [ ] `Session::cleanup_revert(session_id)` 清理截断的消息（revert commit 时调用）
- [ ] Snapshot `rollback_patch` 已实现，直接复用
- [ ] 集成测试：edit → revert → 文件还原；revert → unrevert → 文件恢复
- [ ] SQLite session 表添加 `revert` JSON 字段（迁移 SQL）

**涉及文件**：

- `libs/core/include/turbot/core/session/session.hpp` — 添加 revert 相关方法和字段
- `libs/core/src/session/session.cpp` — 实现 revert/unrevert/cleanup_revert

### 2.8.6 上下文剪枝（prune）

**目标**：压缩前先"修剪"旧工具输出以减少 token 使用，参照 opencode `SessionCompaction.prune()`。

**剪枝规则**：

- 保护最近 `PRUNE_PROTECT = 40,000` tokens 的工具输出
- 超出部分标记为已压缩（清空 output 内容，保留元数据）
- 保护的工具：`skill`（skill 工具结果始终保留）
- 已压缩标记（`compacted_at` 时间戳）的工具不再重复处理
- 最小剪枝量 `PRUNE_MINIMUM = 20,000` tokens，不足时不执行

**验收标准**：

- [x] `SessionCompaction::prune(messages)` 静态方法（含 `PruneConfig` / `PruneResult`）
- [x] `Part` 的 tool 状态增加 `compacted_at` 可选字段（`is_tool_compacted` / `set_tool_compacted_at` / `get_tool_compacted_at`）
- [x] 在 `SessionLoop::run()` 处理 `LoopResult::Compact` 时先调用 prune（两阶段：轻量 prune → full compact）
- [x] Token 估算基于 `estimate_text_tokens`（兼容 2.8.2 精确计数）
- [x] 单元测试：4 个场景覆盖保护窗口 / no-op / exempt_tools / 幂等性（244 assertions / 13 test cases ✅）
- [x] 事件广播：`SessionCompactionEvent` 通过 EventBus 发布（锁外安全）
- [x] CAS 循环防 `token_count_` 负值（`std::max(0, expected - freed)`）
- [x] 代码审查：92/100（A-，所有维度 ≥ A-，Critical/High/Medium/Low 问题 0 个）

**涉及文件**：

- `libs/core/include/turbot/core/session/session_compaction.hpp` — 添加 `prune()` 方法
- `libs/core/src/session/session_compaction.cpp` — 实现 prune

### 2.8.8 question 工具

**目标**：Agent 可暂停执行，向用户提出问题，等待回复后继续。

**设计**（参照 opencode `question.ts` + `question/index.ts`）：

```cpp
// Question.Info 结构（对齐 opencode）
// 工具支持一次传入多个问题（questions 数组）
struct QuestionOption {
    string label;        // 显示文本（1-5 词）
    string description;  // 选项说明
};

struct QuestionInfo {
    string question;             // 完整问题
    string header;               // 短标签（最多 30 字符）
    vector<QuestionOption> options;  // 可选项列表
    optional<bool> multiple;     // 是否允许多选
    optional<bool> custom;       // 是否允许自定义回答（默认 true）
};

class QuestionTool : public Tool {
    string name() { return "question"; }
    // input: { questions: QuestionInfo[] }  // 支持批量提问
    // 执行时：发布 QuestionEvent → 阻塞等待用户回复
    // 用户回复后：返回 ToolResult(answers)
};

// QuestionEvent 通过 Bus 广播（对齐 opencode Question.Event.Asked）
struct QuestionEvent {
    string id;           // question request ID
    string session_id;
    vector<QuestionInfo> questions;
    optional<struct { string message_id; string call_id; }> tool;
};
```

> **注意**：opencode 中 `question` 工具仅在 `OPENCODE_CLIENT` 为 `app/cli/desktop` 或显式启用 `OPENCODE_ENABLE_QUESTION_TOOL` flag 时加载，Turbot 实现时需设计类似的条件注册机制（如配置项或运行时 flag）。

## 七、风险与注意事项

| 风险                                 | 影响                                 | 缓解措施                                                                 |
| ------------------------------------ | ------------------------------------ | ------------------------------------------------------------------------ |
| Bus 引入后 SessionLoop 接口变化      | 破坏已有调用方                       | 保留旧 `set_on_xxx` 接口作为兼容层，内部转 Bus                           |
| Snapshot 存储策略差异（内存 vs git） | Revert 功能 PatchResult 依赖内存缓存 | Revert 仅在 `max_cache_size_mb` 内的文件有效，超限时降级为只截断消息历史 |
| 精确 token 计数改变压缩时机          | 原有集成测试 token 阈值断言可能失效  | 更新测试 mock 的 usage 值                                                |
| Plugin 系统类型安全实现复杂度        | C++ 类型擦除 vs 模板                 | 优先 `std::any` + 命名约定，后续可升级为模板特化                         |
