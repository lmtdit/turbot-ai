# 2.6.1 Critical Bug 修复

> **测试类型**: 单元测试
> **依赖**: 无
> **状态**: 📋 待实现

## 目标

修复 v2.5 代码审核发现的两个 Critical 线程安全问题：

1. **C-1**: `SnapshotManager::active_tracking_count()` 数据竞争（无锁读）
2. **C-2**: `MockProvider::chat_stream()` 持锁调用回调导致潜在死锁
3. **C-4**: `compute_file_hash()` 使用 OpenSSL 弃用 API

---

## 修复内容

### Fix-1: `active_tracking_count()` 加锁

**文件**: `libs/core/include/turbot/core/snapshot/snapshot.hpp:124-126`

```cpp
// 修复前
[[nodiscard]] size_t active_tracking_count() const noexcept {
    return snapshots_.size();  // 未加锁！
}

// 修复后
[[nodiscard]] size_t active_tracking_count() const noexcept {
    std::lock_guard<std::mutex> lock(mutex_);
    return snapshots_.size();
}
```

> **说明**：`snapshots_` 由 `mutex_` 保护，所有读写都需加锁。`noexcept` 可保留，`std::lock_guard` 不会抛异常。

### Fix-2: `MockProvider::chat_stream()` 锁外调用回调

**文件**: `tests/mock/mock_provider.hpp:82-132`

**根本原因**：`chat_stream()` 在持有 `mutex_` 时调用用户 `callback`，而 `callback`（如 E2E-05 的 `loop->stop()`）可能调用 `provider->call_count()` 触发二次加锁，导致递归死锁。

```cpp
// 修复后的 chat_stream()
[[nodiscard]] core::provider::ChatResponse chat_stream(
    const std::vector<core::provider::ChatMessage>& messages,
    const std::string& model_id,
    const core::provider::ChatOptions& options,
    core::provider::StreamCallback callback
) override {
    // 步骤1：在锁内收集所有需要的数据
    std::vector<std::string> local_chunks;
    core::provider::ChatResponse final_response;
    MockError pending_error = MockError::None;

    {
        std::lock_guard<std::mutex> lock(mutex_);
        call_count_++;
        last_messages_ = messages;
        last_model_id_ = model_id;
        last_options_ = options;

        // 检查错误序列
        if (!error_sequence_.empty()) {
            pending_error = error_sequence_.front();
            error_sequence_.pop();
        }

        // 收集 stream chunks（拷贝）
        local_chunks = stream_chunks_;

        // 准备 final response
        if (!responses_.empty()) {
            final_response = responses_.front();
            responses_.pop();
        } else {
            final_response = make_default_response(model_id);
        }
    }
    // 锁已释放

    // 步骤2：锁外处理错误
    if (pending_error != MockError::None) {
        return make_error_response(pending_error);
    }

    // 步骤3：锁外调用 callback（避免死锁）
    if (callback) {
        for (const auto& chunk : local_chunks) {
            core::provider::ChatStreamEvent event;
            event.type = core::provider::StreamEventType::TextDelta;
            event.content = chunk;
            if (!callback(event)) {
                break;  // Stream aborted
            }
        }
        // 发送 finish 事件
        core::provider::ChatStreamEvent finish_event;
        finish_event.type = core::provider::StreamEventType::Finish;
        finish_event.finish_reason = "stop";
        finish_event.usage = core::TokenUsage(100, 50, 150);
        callback(finish_event);
    }

    return final_response;
}
```

### Fix-3: 替换弃用的 OpenSSL SHA-256 API

**文件**: `libs/core/src/snapshot/snapshot.cpp:160-186`

```cpp
// 修复前（弃用 API）
std::string SnapshotManager::compute_file_hash(const std::filesystem::path& path) {
    std::ifstream file(path, std::ios::binary);
    if (!file) return "";

    SHA256_CTX sha256;
    SHA256_Init(&sha256);
    char buffer[8192];
    while (file.read(buffer, sizeof(buffer))) {
        SHA256_Update(&sha256, buffer, file.gcount());
    }
    if (file.gcount() > 0) {
        SHA256_Update(&sha256, buffer, file.gcount());
    }
    unsigned char hash[SHA256_DIGEST_LENGTH];
    SHA256_Final(hash, &sha256);
    // ...
}

// 修复后（使用 turbot::utils 现有函数）
#include <turbot/utils/crypto_utils.hpp>

std::string SnapshotManager::compute_file_hash(const std::filesystem::path& path) {
    auto content = read_file_content(path);
    if (content.empty()) return "";
    return turbot::utils::crypto::sha256(content);
}
```

> **前提**：`turbot::utils::crypto::sha256(const std::string&)` 已在 `libs/utils/include/turbot/utils/crypto_utils.hpp` 中声明并实现，使用现代 EVP API。
