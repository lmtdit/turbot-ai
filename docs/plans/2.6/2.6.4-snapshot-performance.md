# 2.6.4 SnapshotManager 性能优化

> **工时**: 1 天
> **测试类型**: 单元测试
> **依赖**: 2.6.1（Critical 修复完成后再优化）、2.6.3（sha256_file 已可用）
> **状态**: 📋 待实现

---

## 目标

解决 v2.5 审核中识别的三个性能 / 逻辑 Major 问题：

1. **M-1**: `start_tracking()` / `stop_tracking()` 持锁期间执行全目录 IO 扫描（持锁粒度过大）
2. **M-3**: `is_excluded()` 每次调用均重新编译 glob → regex（无预编译缓存）
3. **M-2**: `is_doom_loop()` 接受 `input` 参数但完全不使用（语义缺陷）

---

## 变更详情

### Perf-1: start_tracking / stop_tracking 缩小锁粒度

**文件**: `libs/core/src/snapshot/snapshot.cpp`

**问题**：

```cpp
// 当前实现：持锁扫描整个目录树（可能耗时数秒）
std::string SnapshotManager::start_tracking(const SnapshotOptions& options) {
    std::lock_guard<std::mutex> lock(mutex_);  // 持锁
    // ...
    scan_files(data);           // 全目录 IO 扫描 ← 阻塞所有并发操作
    snapshots_[id] = data;
    return id;
}
```

**修复方案**：将 IO 扫描移出临界区，仅在写 `snapshots_` 时加锁。

```cpp
std::string SnapshotManager::start_tracking(const SnapshotOptions& options) {
    // 步骤 1：在锁外生成 ID，准备数据（无需保护）
    std::string id = turbot::utils::crypto::generate_uuid();

    SnapshotData data;
    data.start_time = std::chrono::system_clock::now();
    data.options = options;

    if (data.options.exclude_patterns.empty()) {
        data.options.exclude_patterns = SnapshotOptions::default_exclude_patterns();
    }
    if (data.options.root_directory.empty()) {
        data.options.root_directory = std::filesystem::current_path();
    }

    // 步骤 2：IO 扫描在锁外执行（耗时操作）
    scan_files(data);

    // 步骤 3：仅在插入 map 时加锁（纳秒级）
    {
        std::lock_guard<std::mutex> lock(mutex_);
        snapshots_[id] = std::move(data);
    }

    TURBOT_LOG_DEBUG("Started snapshot tracking: {}", id);
    return id;
}
```

同理，`stop_tracking()` 的 IO 扫描也应移出锁范围：

```cpp
PatchResult SnapshotManager::stop_tracking(const std::string& snapshot_id) {
    // 步骤 1：加锁取出 data 副本，立即解锁
    SnapshotData data;
    {
        std::lock_guard<std::mutex> lock(mutex_);
        auto it = snapshots_.find(snapshot_id);
        if (it == snapshots_.end()) {
            TURBOT_LOG_ERROR("Snapshot not found: {}", snapshot_id);
            return {};
        }
        data = it->second;        // 复制 data
        snapshots_.erase(it);     // 从 map 移除（持锁）
    }
    // 锁已释放

    // 步骤 2：IO 扫描在锁外执行
    PatchResult result;
    result.id = turbot::utils::crypto::generate_uuid();
    result.snapshot_id = snapshot_id;
    result.created_at = std::chrono::system_clock::now();

    // ... diff 计算逻辑（不变）

    TURBOT_LOG_DEBUG("Stopped snapshot tracking: {}, found {} changes",
              snapshot_id, result.files.size());
    return result;
}
```

**影响**：

- 锁持有时间从「扫描整个目录树」缩短为「map 读写」（ns 级）
- 并发调用 `active_tracking_count()` / `is_tracking()` 不再被 IO 阻塞

### Perf-2: is_excluded() 预编译 glob 正则缓存

**文件**: `libs/core/src/snapshot/snapshot.cpp`

**问题**：每次调用 `is_excluded()` 都重新将 glob 转换为 `std::regex`，`scan_files` 内部对每个文件调用一次，O(N×P) 次编译（N=文件数，P=pattern 数）。

```cpp
// 当前：每次进入循环都 new std::regex
try {
    std::regex re(regex_str);   // ← 每个文件每个 pattern 都重新编译
    if (std::regex_search(path_str, re)) {
```

**修复方案**：在 `SnapshotOptions` / `SnapshotData` 结构中缓存预编译正则。

**新增辅助函数** `libs/core/src/snapshot/snapshot.cpp`：

```cpp
// 将 glob 模式列表转换为预编译的 regex 列表（一次性，不在热路径上）
static std::vector<std::regex> compile_patterns(
    const std::vector<std::string>& patterns
) {
    std::vector<std::regex> result;
    result.reserve(patterns.size());
    for (const auto& pattern : patterns) {
        if (pattern.find('*') == std::string::npos) {
            // 非通配符模式无需编译，用空 regex 占位（跳过）
            result.emplace_back();
            continue;
        }
        std::string regex_str;
        for (char c : pattern) {
            switch (c) {
                case '*': regex_str += ".*"; break;
                case '?': regex_str += ".";  break;
                case '.': case '+': case '[': case ']':
                case '(': case ')': case '{': case '}':
                case '^': case '$': case '|': case '\\':
                    regex_str += '\\';
                    regex_str += c;
                    break;
                default:
                    regex_str += c;
            }
        }
        try {
            result.emplace_back(regex_str);
        } catch (const std::regex_error&) {
            result.emplace_back();  // 无效模式，占位
        }
    }
    return result;
}
```

**修改 `SnapshotData`**（`snapshot.hpp` 或 `snapshot.cpp` 内部）：

```cpp
struct SnapshotData {
    std::chrono::system_clock::time_point start_time;
    SnapshotOptions options;
    std::unordered_map<std::string, std::string> file_hashes;
    std::unordered_map<std::string, std::string> file_contents;
    std::vector<std::regex> compiled_patterns;   // ← 新增：预编译缓存
};
```

**修改 `start_tracking()`**，在 IO 扫描前预编译：

```cpp
// 预编译 glob 模式（在 scan_files 之前）
data.compiled_patterns = compile_patterns(data.options.exclude_patterns);
scan_files(data);
```

**修改 `is_excluded()`** 使用预编译缓存：

```cpp
bool SnapshotManager::is_excluded(
    const std::filesystem::path& path,
    const SnapshotData& data   // ← 改为接受 SnapshotData（含 compiled_patterns）
) {
    std::string path_str = path.string();
    const auto& patterns = data.options.exclude_patterns;

    for (size_t i = 0; i < patterns.size(); ++i) {
        const auto& pattern = patterns[i];
        if (pattern.find('*') != std::string::npos) {
            // 使用预编译正则
            if (std::regex_search(path_str, data.compiled_patterns[i])) {
                return true;
            }
        } else {
            // 精确/前缀匹配（不变）
            if (path_str == pattern ||
                path_str.find(pattern + "/") == 0 ||
                path_str.find("/" + pattern + "/") != std::string::npos) {
                return true;
            }
        }
    }
    return false;
}
```

**影响**：`scan_files` 复杂度从 O(N×P× 编译) 降至 O(N×P× 匹配)，编译开销仅发生一次。

### Logic-1: is_doom_loop() 增加输入比较

**文件**: `libs/core/src/session/session_loop.cpp`

**问题**：`is_doom_loop()` 和 `update_doom_loop_tracking()` 的 `input` 参数从未使用，doom loop 检测仅比较 `tool_name`，语义不完整（相同工具名不同参数应允许连续调用）。

```cpp
// 当前：完全忽略 input
bool SessionLoop::is_doom_loop(const std::string& tool_name, const nlohmann::json& input) const {
    if (tool_name != last_tool_call_) return false;
    return same_tool_count_ >= config_.doom_loop_threshold - 1;
}

void SessionLoop::update_doom_loop_tracking(const std::string& tool_name, const nlohmann::json& input) {
    if (tool_name == last_tool_call_) {
        same_tool_count_++;
    } else {
        last_tool_call_ = tool_name;
        same_tool_count_ = 1;
    }
}
```

**修复方案**：将 `last_tool_input_` 加入跟踪状态，组合键为 `(tool_name, input)`。

**新增成员变量**（`session_loop.hpp`）：

```cpp
// doom loop tracking
mutable std::string last_tool_call_;
mutable nlohmann::json last_tool_input_{};  // ← 新增
mutable int same_tool_count_ = 0;
```

**修改 `is_doom_loop()`**：

```cpp
bool SessionLoop::is_doom_loop(const std::string& tool_name, const nlohmann::json& input) const {
    if (tool_name != last_tool_call_) {
        return false;
    }
    // 相同工具名但不同参数，不视为 doom loop
    if (input != last_tool_input_) {
        return false;
    }
    return same_tool_count_ >= config_.doom_loop_threshold - 1;
}
```

**修改 `update_doom_loop_tracking()`**：

```cpp
void SessionLoop::update_doom_loop_tracking(const std::string& tool_name, const nlohmann::json& input) {
    if (tool_name == last_tool_call_ && input == last_tool_input_) {
        same_tool_count_++;
    } else {
        last_tool_call_ = tool_name;
        last_tool_input_ = input;
        same_tool_count_ = 1;
    }
}
```

**影响**：doom loop 检测更精确，`(tool, input)` 相同才计数，消除了误判。
