# ADR-005: 测试优先原则

| 属性     | 值                                 |
| -------- | ---------------------------------- |
| 编号     | ADR-005                            |
| 标题     | 测试优先原则：以测试为准绳修复实现 |
| 状态     | ✅ 已批准                          |
| 日期     | 2026-03-15                         |
| 影响版本 | v4.3+                              |
| 作者     | Turbot Team                        |

---

## 背景

在 v4.3 测试系统同步过程中，需要明确测试框架与实现代码的关系。当测试框架检测出 Turbot 实现问题时，应该如何处理？

## 决策

### 核心原则

**以测试框架为准，测试不通过时修复实现，而非修改测试。**

### 执行流程

```
测试失败 → 参考 OpenCode 实现 → 修改 Turbot 实现 → 测试通过
         ↑                                          │
         └──────────────────────────────────────────┘
```

### 禁止行为

| 行为                    | 说明                                     |
| ----------------------- | ---------------------------------------- |
| ❌ 修改测试适配错误实现 | 强行修改测试框架来适配 Turbot 的错误实现 |
| ❌ 跳过失败测试         | 跳过失败的测试用例                       |
| ❌ 降低断言标准         | 降低测试断言标准使测试通过               |

### 正确做法

| 行为             | 说明                     |
| ---------------- | ------------------------ |
| ✅ 参考 OpenCode | 参考 OpenCode 的正确实现 |
| ✅ 修复实现      | 修复 Turbot 的实现代码   |
| ✅ 确保权威性    | 确保测试框架的权威性     |

### 例外情况

仅当 Turbot 有意采用与 OpenCode 不同的设计决策时，才可调整测试。此类调整需要满足：

1. 明确的 ADR (Architecture Decision Record) 支持
2. 记录设计差异的原因
3. 测试调整需经过评审

## 理由

1. **测试即规范**：测试用例定义了系统的预期行为，是活文档
2. **质量保障**：修改测试来适配错误实现会掩盖真正的 bug
3. **一致性**：参考 OpenCode 的成熟实现可避免重复踩坑
4. **可维护性**：保持测试的权威性有助于长期维护

## 影响

### 正面影响

- 提高代码质量，减少隐藏 bug
- 保持测试框架的权威性和可信度
- 促进 Turbot 与 OpenCode 的功能对齐
- 形成良性的测试驱动开发循环

### 风险

- 可能需要更多时间修复实现代码
- 某些边缘情况可能需要更深入的分析

### 缓解措施

- 参考 OpenCode 的成熟实现可加速修复
- 例外机制确保合理的灵活性

## 适用范围

- v4.3 测试系统同步
- 所有后续测试开发
- 代码审查时的问题判定
- CI/CD 流水线的质量门禁
