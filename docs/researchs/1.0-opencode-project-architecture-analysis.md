# OpenCode 项目架构设计/核心概念/核心流程技术分析报告

## 1. 项目概述

OpenCode 是一个基于 TypeScript/Bun 的 AI 驱动代码开发助手，采用 CLI 架构设计，提供本地化、可扩展的智能编码辅助功能。项目位于 `opencode/packages/opencode` 目录，核心依赖包括：

- **运行时**: Bun 1.2.12+
- **数据库**: Drizzle ORM + SQLite
- **AI 集成**: Vercel AI SDK（支持 20+ AI 提供商）
- **语言服务**: LSP (Language Server Protocol)
- **代码解析**: tree-sitter
- **工具系统**: MCP (Model Context Protocol)

## 2. 核心架构设计

## 3. 核心概念

### 3.1 Session（会话）

**定义**: Session 是 OpenCode 的核心概念，代表一次完整的 AI 交互对话。

**数据模型** (`session/session.sql.ts`):

```typescript
SessionTable {
  id: string                    // 主键
  project_id: string            // 关联项目
  workspace_id: string?         // 工作空间（可选）
  parent_id: string?            // 父会话（支持 fork）
  slug: string                  // URL 友好标识
  directory: string             // 工作目录
  title: string                 // 会话标题
  version: string               // OpenCode 版本
  share_url: string?            // 分享链接
  summary_additions: integer?   // 添加行数摘要
  summary_deletions: integer?   // 删除行数摘要
  summary_files: integer?       // 修改文件数摘要
  summary_diffs: JSON?          // 差异详情
  revert: JSON?                 // 回滚信息
  permission: JSON?             // 权限规则集
  time_created: integer         // 创建时间
  time_updated: integer         // 更新时间
  time_compacting: integer?     // 压缩时间
  time_archived: integer?       // 归档时间
}
```

**核心特性**:
- **层级结构**: 支持父子会话关系，允许 fork 会话
- **版本控制**: 跟踪 OpenCode 版本，支持升级迁移
- **摘要统计**: 自动统计代码变更（添加/删除行数、文件数）
- **权限控制**: 每个会话独立的权限规则集
- **分享功能**: 支持会话分享（通过 ShareNext）
- **快照回滚**: 记录关键点，支持回滚到指定状态

**关键操作**:
```typescript
// 创建会话
Session.create({ parentID, title, permission })

// Fork 会话
Session.fork({ sessionID, messageID })

// 更新标题
Session.setTitle({ sessionID, title })

// 设置权限
Session.setPermission({ sessionID, permission })

// 设置回滚点
Session.setRevert({ sessionID, revert, summary })

// 获取消息列表
Session.messages({ sessionID, limit })
```


**关键特性**:
- **流式处理**: 支持实时流式传输消息内容
- **多类型 Part**: 文本、工具调用、推理、快照、补丁等
- **成本追踪**: 自动计算 token 使用和成本
- **错误处理**: 记录错误信息，支持重试
- **父子关系**: 支持消息链式追踪

### 3.3 Agent（代理）

**定义**: Agent 是 AI 代理的抽象，定义了代理的行为、权限和提示词。

**数据模型** (`agent/agent.ts`):

```typescript
Agent.Info {
  name: string                // 代理名称
  description?: string        // 描述
  mode: "subagent" | "primary" | "all"
  native?: boolean            // 是否内置
  hidden?: boolean            // 是否隐藏
  topP?: number               // Top-P 采样
  temperature?: number        // 温度参数
  color?: string              // UI 颜色
  permission: PermissionNext.Ruleset  // 权限规则集
  model?: {                   // 模型配置
    modelID: string
    providerID: string
  }
  variant?: string            // 模型变体
  prompt?: string             // 自定义提示词
  options: Record<string, any>  // 其他选项
  steps?: number              // 最大步骤数
}
```

**内置代理**:

1. **build**: 默认代理，执行工具操作
2. **plan**: 计划模式，禁用编辑工具
3. **general**: 通用代理，用于研究和多步任务
4. **explore**: 探索代理，快速查找文件和代码
5. **compaction**: 压缩代理（隐藏）
6. **title**: 标题生成代理（隐藏）
7. **summary**: 摘要生成代理（隐藏）

**权限系统**:

```typescript
PermissionNext.Ruleset = Rule[]

  permission: string          // 权限类型（edit, read, bash 等）
  pattern: string             // 匹配模式（支持通配符）

}
```

**默认权限**:
```typescript

  }
```


## 4. 核心流程

### 4.1 会话创建流程

```
用户执行: opencode run
    ↓
1. 加载项目配置
   - 读取 opencode.json
   - 初始化数据库
   - 加载权限规则
    ↓
2. 创建会话
   - 生成会话 ID
   - 关联项目 ID
   - 设置标题和目录
   - 应用默认权限
    ↓
3. 初始化消息
   - 创建用户消息
   - 调用初始化命令 (init)
   - 生成 AGENTS.md
    ↓
4. 启动处理器
   - 选择代理
   - 加载工具
   - 开始流式处理
    ↓
5. 交互循环
   - 等待用户输入
   - 调用 LLM
   - 执行工具
   - 更新状态
```

**代码流程** (`cli/cmd/run.ts` → `session/index.ts`):

```typescript
// 1. 创建会话
const session = await Session.create({
  title: input.title,
  permission: input.permission
})

// 2. 初始化消息
const message = await MessageV2.create({
  sessionID: session.id,
  role: "user",
  content: input.prompt
})

// 3. 初始化
await Session.initialize({
  sessionID: session.id,
  modelID: model.id,
  providerID: model.providerID,
  messageID: message.id
})

// 4. 处理器
const processor = SessionProcessor.create({
  assistantMessage,
  sessionID: session.id,
  model,
  abort: abortController.signal
})

// 5. 流式处理
const result = await processor.process({
  user: userMessage,
  sessionID: session.id,
  model,
  agent,
  system: [],
  abort: abortController.signal,
  messages: history,
  tools: toolRegistry,
})
```

### 4.2 LLM 调用流程

```
1. 准备输入
   - 构建系统提示词
   - 准备消息历史
   - 加载工具定义
    ↓
2. 选择模型
   - 获取模型配置
   - 应用代理参数
   - 设置选项（temperature, topP, topK）
    ↓
3. 调用 LLM
   - 使用 Vercel AI SDK
   - 流式传输响应
   - 处理中间状态
    ↓
4. 处理响应
   - 解析文本部分
   - 解析工具调用
   - 处理推理过程
    ↓
5. 执行工具
   - 权限检查
   - 执行工具逻辑
   - 返回结果
    ↓
6. 更新状态
   - 更新消息 Part
   - 计算成本
   - 记录快照
    ↓
7. 继续对话
   - 检查完成条件
   - 决定是否继续
   - 重复步骤 3-6
```

**代码流程** (`session/llm.ts` + `session/processor.ts`):

```typescript
// 1. 流式调用
const stream = await LLM.stream({
  user: userMessage,
  sessionID,
  model,
  agent,
  system: systemPrompts,
  abort,
  messages: history,
  tools: toolRegistry,
})

// 2. 处理流式响应
for await (const value of stream.fullStream) {
  switch (value.type) {
    case "text-start":
      // 开始文本部分
      const textPart = { type: "text", text: "", ... }
      await Session.updatePart(textPart)
      break

    case "text-delta":
      // 文本增量
      textPart.text += value.text
      await Session.updatePartDelta({ field: "text", delta: value.text })
      break

    case "tool-call":
      // 工具调用
      const toolPart = { type: "tool", tool: value.toolName, ... }
      await Session.updatePart(toolPart)
      // 执行工具
      const result = await toolRegistry[value.toolName].execute(value.input)
      await Session.updatePart({ ...toolPart, state: { status: "completed", output: result } })
      break

    case "finish-step":
      // 步骤完成
      const usage = Session.getUsage({ model, usage: value.usage })
      await Session.updatePart({
        type: "step-finish",
        tokens: usage.tokens,
        cost: usage.cost
      })
      break
  }
}
```

### 4.3 工具执行流程

```
1. AI 决定调用工具
   - 解析工具名称
   - 解析参数
   - 生成调用 ID
    ↓
2. 权限检查
   - 评估权限规则
   - 决定 allow/deny/ask
    ↓
3a. 允许
    ↓
   执行工具
    ↓
   返回结果
    ↓
3b. 拒绝
    ↓
   返回错误
    ↓
3c. 询问
    ↓
   发布询问事件
    ↓
   等待用户回复
    ↓
   根据回复继续/拒绝
    ↓
4. 更新 Part
   - 设置工具状态
   - 记录输出
   - 计算耗时
    ↓
5. 继续对话
   - 将工具结果返回给 LLM
   - 继续流式处理
```

**代码流程** (`permission/next.ts` + `tool/*.ts`):

```typescript
// 1. 权限检查
try {
  await PermissionNext.ask({
    permission: "edit",
    patterns: [filePath],
    ruleset: agent.permission,
    sessionID,
    metadata: { tool: "edit", input }
  })
} catch (e) {
  if (e instanceof PermissionNext.RejectedError) {
    // 用户拒绝
    await Session.updatePart({ state: { status: "error", error: "User rejected" } })
    return
  }
}

// 2. 执行工具
const result = await tool.execute(input)

// 3. 更新状态
await Session.updatePart({
  state: {
    status: "completed",
    output: result,
    time: { start, end: Date.now() }
  }
})
```

### 4.4 权限评估流程

```
1. 接收权限请求
   - 权限类型（edit, read, bash 等）
   - 匹配模式（文件路径等）
   - 规则集（代理权限 + 项目权限）
    ↓
2. 规则匹配
   - 遍历规则集
   - 使用通配符匹配
   - 找到最后匹配的规则
    ↓
3a. Allow
    ↓
   继续执行
    ↓
3b. Deny
    ↓
   抛出 DeniedError
    ↓
3c. Ask
    ↓
   发布询问事件
    ↓
   等待用户回复
    ↓
   Once: 允许一次
    ↓
   Always: 永久允许
    ↓
   Reject: 拒绝
```

**代码流程** (`permission/next.ts`):

```typescript
function evaluate(permission: string, pattern: string, ...rulesets: Ruleset[]): Rule {
  const merged = merge(...rulesets)

  // 找到最后匹配的规则
  const match = merged.findLast(
    (rule) => Wildcard.match(permission, rule.permission) &&
             Wildcard.match(pattern, rule.pattern)
  )

  // 默认询问
  return match ?? { action: "ask", permission, pattern: "*" }
}

// 使用示例
const rule = evaluate("edit", "/path/to/file.ts", agent.permission, project.permission)
if (rule.action === "deny") throw new DeniedError([rule])
if (rule.action === "ask") await askUser()
```

### 4.5 会话压缩流程

```
1. 检测触发条件
   - Token 超过阈值
   - 消息数量过多
   - 配置要求
    ↓
2. 创建压缩会话
   - Fork 原始会话
   - 生成摘要
   - 保留关键消息
    ↓
3. 生成摘要
   - 调用 summary 代理
   - 提取关键信息
   - 压缩历史消息
    ↓
4. 更新原会话
   - 设置压缩标记
   - 保存摘要信息
   - 清理旧消息
    ↓
5. 继续对话
   - 使用压缩后的历史
   - 减少上下文长度
```

**代码流程** (`session/compaction.ts`):

```typescript
// 检测是否需要压缩
if (await SessionCompaction.isOverflow({ tokens: usage.tokens, model })) {
  // 执行压缩
  await SessionCompaction.compact({
    sessionID,
    messageID: currentMessage.id
  })
}

// 压缩逻辑
async function compact(input) {
  // 1. Fork 会话
  const forked = await Session.fork({ sessionID: input.sessionID })

  // 2. 生成摘要
  const summary = await Agent.summary.generate({
    messages: await Session.messages({ sessionID: input.sessionID })
  })

  // 3. 更新原会话
  await Session.setSummary({
    sessionID: input.sessionID,
    summary
  })

  // 4. 标记压缩时间
  await Session.setCompacting({ sessionID: input.sessionID, time: Date.now() })
}
```

### 4.6 快照和回滚流程

```
1. 开始步骤
   - 创建文件系统快照
   - 记录当前状态
   - 生成快照哈希
    ↓
2. 执行操作
   - 修改文件
   - 执行工具
   - 更新代码
    ↓

   - 计算差异

   - 计算统计信息
   - 更新摘要
```

```typescript
const snapshot = await Snapshot.track()

// 2. 完成步骤
const patch = await Snapshot.patch(snapshot)
if (patch.files.length) {

    type: "patch",
    hash: patch.hash,
    files: patch.files
  })
```
