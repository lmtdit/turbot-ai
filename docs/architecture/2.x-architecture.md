| 库             | 依赖关系                      | 说明                          |

| `apps/*`       | core, storage, network, utils | 应用层可依赖所有库            |

## 2. 核心流程

### 2.1 SessionLoop 主循环

`SessionLoop::run(user_message)` 是整个系统的主入口：

```
SessionLoop::run(user_message)
  │
  ├─[前置检查] provider_ 非空 && model_id_ 非空
  │   失败 → return LoopResult::Error
  │
  ├─[重置状态] tool_defs_dirty_ = true
  │           running_ = true, stop_requested_ = false
  │           iteration_count_ = 0
  │
  ├─ process_user_message(user_message)
  │   └─ 构造 Message(Role::User) → 加入 messages_
  │       → 触发 on_message_ 回调
  │
  └─ while (result == Continue && !stop_requested_)
        └─ result = step()
              │
              ├─[压缩检查] needs_compaction()？
              │   token_count_ >= config_.compact_threshold
              │   → return LoopResult::Compact
              │
              ├─[迭代上限] iteration_count_ >= config_.max_iterations
              │   → return LoopResult::Stop
              │
              └─ process_llm_response()
                    │
                    ├─ build_llm_messages()     // 从 messages_ 构建对话历史
                    ├─ build_tool_definitions() // 懒加载：tool_defs_dirty_ 控制
                    │
                    ├─ LLM::stream(*provider_, model_id_, params, handler)
                    │   └─ 流式调用，handler 触发 on_stream_event_ 回调
                    │
                    ├─[错误] result.has_error() → return Error
                    │
                    ├─[无工具调用] finish_reason == Stop → return Stop
                    │
                    └─[有工具调用] for each tool_call:
                           │
                           ├─[死循环检测] is_doom_loop(name, input)?
                           │   same_tool_count_ >= doom_loop_threshold → return Stop
                           │
                           ├─ execute_tool(name, call_id, input)
                           │   ├─ ToolRegistry::instance().get(name)
                           │   ├─ tool->execute(input, ctx) [with try-catch]
                           │   ├─ 触发 on_tool_call_ / on_tool_result_ 回调
                           │   └─ 结果写入 messages_
                           │
                           └─ update_doom_loop_tracking(name, input)
```

### 2.2 流式响应处理

LLM 流式调用的事件流：

```
LLM::stream()
  → Provider::chat_stream() [底层 HTTP SSE]
  → StreamCallback 逐事件回调
  → StreamingState::add_event(event)

事件类型（StreamEventType）:
  Start           → 流开始
  TextStart       → 文本段开始
  TextDelta       → 文本内容增量
  TextEnd         → 文本段结束
  ReasoningStart  → 推理段开始（o1/thinking 模型）
  ReasoningDelta  → 推理内容增量
  ReasoningEnd    → 推理段结束
  ToolInputStart  → 工具调用开始
  ToolInputDelta  → 工具参数增量（JSON streaming）
  ToolInputEnd    → 工具参数完整
  ToolCall        → 完整工具调用（非流式）
  StepStart       → Agent 步骤开始
  StepFinish      → Agent 步骤结束
  SourceStart     → 引用来源开始（v2.0）
  SourceEnd       → 引用来源结束（v2.0）
  Finish          → 流结束（含 FinishReason + TokenUsage）
  Error           → 错误

FinishReason:
  Stop / Length / ToolCall / ContentFilter / Error / Other
```

### 2.3 工具执行流程

```
SessionLoop::execute_tool(tool_name, call_id, input)
  │
  ├─ ToolRegistry::instance().get(tool_name)
  │   未找到 → ToolResult::error("Unknown tool: ...")
  │
  ├─ 构造 ToolContext {
  │       session_id, message_id, agent,
  │       call_id, working_directory,
  │       on_metadata (回调),
  │       ask_permission (权限请求回调),
  │       ruleset (当前权限规则集),
  │       tool_config (默认超时 120s, 最大 600s),
  │       abort_flag (shared_ptr<atomic<bool>>)
  │   }
  │
  ├─ try { result = tool->execute(input, ctx) }
  │   catch(...) → ToolResult::error(exception_msg)
  │
  └─ 触发 on_tool_result_ 回调
     将结果以 ToolResult 消息追加到 messages_
```

**9 个内置工具**（builtin/）：

| 工具名       | 源文件              | 主要功能                           |
| ------------ | ------------------- | ---------------------------------- |
| `read_file`  | read_file_tool.cpp  | 读取文件内容，支持行范围           |
| `write_file` | write_file_tool.cpp | 写入文件（覆盖/追加）              |
| `edit`       | edit_tool.cpp       | 精确字符串替换，批量 fsync         |
| `bash`       | bash_tool.cpp       | 执行 shell 命令，支持超时          |
| `glob`       | glob_tool.cpp       | 文件模式匹配搜索                   |
| `grep`       | grep_tool.cpp       | 文件内容正则搜索（基于 ripgrep）   |
| `list`       | list_tool.cpp       | 列出目录内容                       |
| `task`       | task_tool.cpp       | 派发子 Agent 任务（多 Agent 协作） |

> `fs_tool_common.hpp` 是内部共享头文件（SHA-256 哈希、文件工具公共逻辑），不注册为工具。

### 2.4 多 Agent 协作

```
Primary Agent (SessionLoop)
  │
  │ [task 工具调用]
  ├─ task_tool.cpp::execute()
  │   ├─ 从 AgentRegistry::instance() 查找子 Agent
  │   ├─ 构造 ExecuteParams { session_id, prompt, context }
  │   ├─ subagent->execute(params)
  │   │     └─ 内部可创建独立的 SessionLoop
  │   └─ 返回 ToolResult (ExecuteResult.output)
  │
  └─ 主 Agent 将子 Agent 输出纳入对话历史继续推进
```

AgentInfo 扩展字段（v2.0）：

| 字段          | 类型               | 说明                             |
| ------------- | ------------------ | -------------------------------- |
| `prompt`      | `optional<string>` | Agent 专属系统提示模板           |
| `temperature` | `optional<double>` | 生成温度（0.0–2.0，validated）   |
| `top_p`       | `optional<double>` | Top-p 采样（0.0–1.0，validated） |
| `steps`       | `optional<int>`    | 最大执行步数（>= 1，validated）  |
| `color`       | `optional<string>` | UI 颜色（`#RRGGBB` 或颜色名）    |
| `variant`     | `optional<string>` | 模型变体标识                     |

**动态生成 Agent**（`agent_generator` 命名空间）：

```cpp
agent_generator::GenerateParams p;
p.description = "专门分析安全漏洞的 Agent";
AgentGenerateResult result = agent_generator::generate(p);
// result.identifier / result.system_prompt / result.when_to_use
AgentInfo info = result.to_agent_info();
```

### 2.5 文件快照与回滚

```
// 开始追踪
SnapshotOptions opts;
opts.root_directory = "/path/to/project";
opts.max_cache_size_mb = 50;  // 内容缓存上限，超限仅记 hash
string snap_id = SnapshotManager::instance().start_tracking(opts);

// ... 工具执行修改文件 ...

// 停止追踪，获取变更
PatchResult patch = SnapshotManager::instance().stop_tracking(snap_id);
// patch.files: vector<FileChange> { path, type(Created/Modified/Deleted), old_content, new_content, hash }

// 回滚
SnapshotManager::instance().rollback_patch(patch);
// 内部对所有受影响目录执行 POSIX fsync（批量）
```

排除模式（`exclude_patterns`）支持 glob，在 `SnapshotData::compiled_patterns` 中预编译为 `optional<regex>`。

### 2.6 会话压缩

```
// 触发条件：token_count_ >= compact_threshold（默认 100000）
// SessionLoop::step() 返回 LoopResult::Compact

CompactionConfig cfg;
cfg.overflow_threshold = 0.9;   // 上下文使用率
cfg.target_ratio = 0.5;         // 目标压缩比
cfg.min_messages_to_keep = 5;   // 至少保留消息数
cfg.max_summary_length = 2000;  // 摘要最大长度

SessionCompaction compactor;
compactor.set_summary_generator([](const vector<Message>& msgs) {
    // 通过 LLM 生成摘要
    return llm_summarize(msgs);
});

CompactionResult result = compactor.compact(messages, cfg);
// result.summary         → 摘要文本
// result.retained_ids    → 保留消息 ID
// result.removed_ids     → 移除消息 ID
// result.compression_ratio → 压缩比（0–1）
```

消息重要性评分规则（`MessageImportance`）：

- 包含工具调用 → 提高权重
- 包含工具结果 → 提高权重
- 系统消息 → 最高权重（不删）
- 位置靠后 → 权重更高（保留最新）

## 3. 模块详解

### 3.1 SessionLoop（核心交互循环）

**头文件**：`turbot/core/session/session_loop.hpp`  
**命名空间**：`turbot::core::session`

```cpp
enum class LoopResult { Continue, Stop, Compact, Error };

struct SessionLoopConfig {
    int max_iterations = 100;        // 最大迭代次数
    int max_tokens = 128000;         // token 上限
    int compact_threshold = 100000;  // 压缩触发阈值
    bool auto_compact = true;        // 自动触发压缩
    int doom_loop_threshold = 3;     // 死循环检测阈值（连续相同工具调用）
};

struct StepInfo {
    int step_number;
    string message_id;
    TokenUsage tokens;
    double cost;
    bool has_tool_calls;
    vector<string> tool_names;
};
```

**6 种回调**：`on_message_`、`on_tool_call_`、`on_tool_result_`、`on_error_`、`on_stream_event_`、`on_step_`

**关键内部状态**：

- `abort_flag_`：`shared_ptr<atomic<bool>>`，透传给 ToolContext，工具可中途检查
- `tool_defs_dirty_`：每次 `run()` 重置为 true，首次 `step()` 构建工具定义后复用
- `same_tool_count_`：死循环计数器，超过 `doom_loop_threshold` 时停止

### 3.2 LLM 层

**头文件**：`turbot/core/llm/llm.hpp`、`stream_event.hpp`、`message_builder.hpp`

核心接口：

```cpp
// 静态方法，流式调用
LLMStreamResult LLM::stream(
    Provider& provider,
    const string& model_id,
    const StreamParams& params,
    StreamEventHandler handler = nullptr  // 每个事件的回调
);

// 参数结构
struct StreamParams {
    string session_id;
    vector<LLMMessage> messages;
    vector<LLMToolDefinition> tools;
    optional<string> tool_choice;
    double temperature = 1.0;
    optional<double> top_p;
    optional<int> max_tokens;
    vector<string> stop;
    function<bool()> is_aborted;  // abort 检查回调
};
```

`LLMStreamResult` 提供：

- `next()` → 阻塞直到有下一个事件
- `collect()` → 阻塞直到全部完成
- `tool_calls()` → 最终累积的工具调用列表
- `has_error()` / `error()` → 错误检查

### 3.4 Agent 系统

**头文件**：`turbot/core/agent/agent.hpp`

- `Agent`：抽象基类，子类实现 `execute(ExecuteParams) → ExecuteResult`

### 3.5 Tool 系统

**头文件**：`turbot/core/tool/tool.hpp`、`tool_registry.hpp`

class Tool {

### 3.7 Session（会话管理）

**头文件**：`turbot/core/session/session.hpp`

```cpp
enum class SessionState {
    Created,    // 刚创建，未激活
    Active,     // 活跃，可接受交互
    Busy,       // 正在处理请求
    Compacting, // 正在压缩
    Archived    // 已归档（只读）
};
```

状态转换（`SessionStateMachine`）：

```
Created → Active → Busy → Active
                ↓
           Compacting → Active
                ↓
            Archived (终态)
```

支持 fork（`Session::fork(ForkParams)`）：以指定父会话为基础创建分支会话。

### 3.9 Permission（权限系统）

**头文件**：`turbot/core/permission/permission.hpp`

```cpp
// 评估规则（最后匹配规则胜出）
PermissionAction result = PermissionSystem::evaluate(
    "write",           // 权限类型
    "/path/to/file",   // 资源路径
    ruleset            // 规则集（vector<PermissionRule>）
);
// 默认（无匹配）→ Deny

// 权限请求/回复
struct PermissionReply {
    enum class Type { Once, Always, Reject };
};
```

权限评估在 `ToolContext::ask_permission` 回调中触发，支持 `Once`（一次性）和 `Always`（永久加入 Ruleset）两种授权模式。通配符匹配支持 `*`（任意序列）和 `?`（单字符）。

### 3.10 ConfigManager（配置管理）

### 3.11 Snapshot（文件快照）

**头文件**：`turbot/core/snapshot/snapshot.hpp`

关键实现细节：

- `max_cache_size_mb = 50`：超出内存缓存上限的文件只记 SHA-256 哈希（`old_content = ""`）
- `compiled_patterns`：glob 排除模式在 `start_tracking()` 时预编译为 `optional<regex>`（非 glob 模式置 `nullopt`）
- `apply_patch` / `rollback_patch`：操作完成后对所有受影响目录执行 POSIX `fsync`（批量）

## 5. 并发与线程安全

### 5.1 锁规约

| 锁                        | 保护对象                | 规则                              |
| ------------------------- | ----------------------- | --------------------------------- |
| `agent_mutex_`            | SessionLoop::agent\_    | 必须先于 messages*mutex* 获取     |
| `messages_mutex_`         | SessionLoop::messages\_ | 获取前不可持有 agent*mutex*       |
| `AgentRegistry::mutex_`   | agents\_ map            | `shared_mutex`（读写锁）          |
| `ToolRegistry::mutex_`    | tools\_ map             | `shared_mutex`（读写锁）          |
| `SnapshotManager::mutex_` | snapshots\_ map         | `mutex`（独占锁）                 |
| `UsageTracker::mutex_`    | sessions\_ map          | `mutex`（独占锁）                 |
| `ConfigManager::mutex_`   | merged*config*          | `mutex`（独占锁）                 |
| `ProviderManager::mutex_` | providers*, factories*  | `mutex`（独占锁，声明为 mutable） |

> **死锁预防规则**：`agent_mutex_` → `messages_mutex_`，严禁反向获取。

### 5.2 Abort 机制

```cpp
// abort_flag_ 是 SessionLoop 的 shared_ptr<atomic<bool>>
// 同一实例透传给所有工具执行的 ToolContext

SessionLoop::stop()
  └─ abort_flag_->store(true)
     stop_requested_.store(true)

// 工具内检查
ToolContext::should_abort()
  └─ abort_flag->load(memory_order_relaxed)
```

### 5.3 SessionLoop 并发规则

- `run()` 通过 `running_` 原子标志语义上保证单线程执行
- `messages()` 提供线程安全的拷贝视图
- `token_count()` / `step_number()` 使用 `memory_order_relaxed` 的原子读（允许 stale）
- `total_usage()` / `total_cost()` 仅在 `run()` 完成后读取（非线程安全）
