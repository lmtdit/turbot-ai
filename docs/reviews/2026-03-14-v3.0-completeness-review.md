## 三、LSP 系统（目标对齐 OpenCode `src/lsp/server.ts` 2098行）

### ✅ 已完成

- `LSPClient`（`client.cpp` 798行）：Content-Length framing 手工实现，`kDiagnosticsDebounceMs = 150`（对齐 OpenCode `DIAGNOSTICS_DEBOUNCE_MS = 150`），3s 超时

### ⚠️ 已发现问题

**[MEDIUM] LSP 覆盖语言服务器仅 3 种 vs OpenCode 8 种**

OpenCode 支持 Deno/TS/Vue/ESLint/Oxlint/Biome/Gopls/Clangd 等8种，Turbot 当前只有 Clangd/Pyright/Gopls，符合计划范围，**但计划将其标记为完成（✅ 91/100），与实际覆盖范围存在预期差**。

**[LOW] LSP `server.cpp` 极小（2.2KB）**

实际功能看似集中在 `client.cpp`，`server.cpp` 职责不清晰，可能存在模块边界模糊。

## 四、ACP 系统（目标对齐 OpenCode `src/acp/agent.ts` 1744行）

### ✅ 已完成

- `TurbotACPAgent`（`agent.cpp` 696行）：`initialize`/`new_session`/`load_session`/`resume_session`/`list_sessions`/`fork_session`/`prompt`/`cancel` 全部实现
- 流式更新：`on_update` 回调驱动 `agent_message_chunk`/`tool_call`/`tool_call_update`/`plan`/`usage_update`
- **Session 历史回放**（`load_session` 调用 `process_message` 逐条回放）— 超越 OpenCode 缺陷6
- `todowrite` 工具 plan 通知对齐 OpenCode，`cancelled → completed` 映射
- `to_tool_kind` 映射对齐 OpenCode `toToolKind`
- `ACPServer`（`server.cpp` 11KB）：JSON-RPC over stdio 实现
- ACP Session Manager（`session.cpp` 6KB）

### ⚠️ 已发现问题

**[HIGH] ACP `cancel()` 方法为 stub**

```cpp
// acp/agent.cpp line 448
// This stub satisfies the interface contract.
```

`cancel()` 的停止信号通路尚未建立（SessionLoop 无 stop handle 暴露给 agent.cpp），当前为 no-op。

**[CRITICAL] 权限系统全路旁路（SessionLoop 未注入 ask_permission）**

二次核实发现（v2.x / v3.0 共同问题）：`SessionLoop::execute_tool()` 构建 `ToolContext`（line 700）时从未设置 `ask_permission` 回调：

```cpp
// session_loop.cpp:700
tool::ToolContext ctx;
ctx.session_id = session_.id();
// …其他字段…
// ask_permission 从未设置
```

结果：所有工具 `if (!ctx.ask_permission)` 检查均跳过权限确认，直接执行。`permission.cpp` 规则引擎从未被触发。

> OpenCode 对比：`permission.asked` EventBus 事件 → ACP `requestPermission()` → 用户确认完整闭环，Turbot 中该链路未建立。

**[MEDIUM] `set_on_tool_result` 回调路径 diff 块内容为空**

```cpp
// acp/agent.cpp line 384-390
// Edit tool completed: add diff block (aligned with OpenCode)
// rawInput not available in result callback; emit empty-path diff
content.push_back({{"type", "diff"},
                   {"path", ""},
                   {"oldText", ""},
                   {"newText", ""}});
```

> 注：`load_session` 历史回放路径（line 609-615）已从 `args`（`oldString`/`newString`）正确提取 diff 内容，弹流路径的占位为主要问题。工具结果回调未传入 `rawInput`，导致 IDE 展示文件变更的 diff 内容丢失，不符合 OpenCode 预期。

## 五、Session 基础层（v2.x 遗留问题）

### ⚠️ 已发现问题

**[CRITICAL] Session.get / Session.list / Session.delete 均为占位实现**

```cpp
// session.cpp line 231-250
// This is a placeholder - in a real implementation,
// this would query the database
(void)id;
return std::nullopt;  // get()
return {};            // list()
return false;         // delete()
```

这三个方法是 ACP 全部 session 操作的底层依赖：

- `ACP.load_session` → `Session::get()` → 返回 `nullopt` → 立即抛异常
- `ACP.list_sessions` → `Session::list()` → 永远返回空列表
- `ACP.fork_session` → `Session::get()` → 永远失败

**影响**：ACP 的 `load_session`/`list_sessions`/`fork_session` 在当前代码下全部无法正常工作，ACP 有效功能仅限 `new_session + prompt`。
