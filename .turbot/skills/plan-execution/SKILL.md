# 计划按步骤实施

## 触发条件

当用户请求满足以下任一条件时自动触发：

| 触发词   | 示例                           |
| -------- | ------------------------------ |
| 执行计划 | "执行开发计划"、"开始执行计划" |
| 实施计划 | "实施这个计划"、"开始实施"     |
| 开始计划 | "开始计划"、"启动计划"         |
| 继续执行 | "继续执行计划"、"继续实施"     |

**注意**：计划执行过程中每步完成后自动应用此技能。

## 核心流程

```
1. 解析计划 → 识别步骤和依赖
2. 排序执行 → 按依赖顺序执行
3. 逐步验证 → 每步完成后立即验证
4. 进度追踪 → 更新状态，记录结果
```

## 可测试性检查

每步执行前确认：

- [ ] 有明确的输入/输出定义
- [ ] 有可验证的验收标准
- [ ] 可独立测试（单元测试/Mock 测试）

**检查不通过时暂停，要求补充计划。**

## 执行与验证

执行流程：

1. 显示当前步骤
2. 执行操作
3. 运行验证测试
4. 记录结果
5. 失败时 → 显示错误、提供修复建议、暂停等待决策

**验证方法**：代码用单元测试，API 用集成测试，配置用检查脚本。

## 回滚策略

| 变更类型 | 回滚方法         |
| -------- | ---------------- |
| 代码变更 | git revert/reset |
| 新建文件 | 删除文件         |
| 配置修改 | 恢复原配置       |

## 进度报告模板

```markdown
**计划名称**: [计划名称]
**执行时间**: [开始时间] - [当前时间]
**总体进度**: [已完成]/[总步骤] ([百分比]%)

| 步骤   | 状态      | 开始时间 | 完成时间 | 备注       |
| ------ | --------- | -------- | -------- | ---------- |
| 步骤 1 | ✅ 完成   | 10:00    | 10:15    | -          |
| 步骤 2 | 🔄 进行中 | 10:15    | -        | -          |
| 步骤 3 | ⏸️ 待执行 | -        | -        | 等待步骤 2 |
| 步骤 4 | ❌ 失败   | 10:30    | 10:35    | 需要修复   |
```

## 核心原则

1. **可测试性优先** - 不可测试的步骤不执行
2. **逐步验证** - 每步完成立即验证，不累积问题
3. **失败即停** - 验证失败暂停，等待用户决策
4. **保持可回滚** - 每步操作应可回滚

## 项目实施规则

每个模块实施后必须执行：

### 1. 单元测试

- 模块实现后立即补充单元测试
- 覆盖率要求：≥ 90%
- 测试通过后方可进入审查阶段

### 2. 代码审查

- 模块完成后调用 `code-reviewer` agent 执行审查
- 最多迭代 3 次修复问题
- 每次修复后重新审查

### 3. 退出条件

| 维度     | 最低评级 |
| -------- | -------- |
| 架构     | A        |
| 安全     | A        |
| 代码质量 | A-       |
| 可维护性 | A-       |

**未达标时继续修复，直到满足退出条件或达到迭代上限。**

## 自动执行后续计划

当当前计划满足以下条件时，可自动执行后续计划：

### 触发条件

- [ ] 所有步骤已完成
- [ ] 退出条件评级全部达标
- [ ] 用户未明确要求暂停

### 执行流程

```
当前计划完成
    ↓
检查退出条件
    ↓ 达标
检查是否有后续计划
    ↓ 有
提示用户确认
    ↓ 确认
自动开始后续计划
```

### 后续计划识别

按以下顺序查找后续计划：

1. **显式链接**：当前计划文档中标注的 `后续计划` 或 `Next Plan` 字段
2. **命名约定**：同目录下的计划文件，按命名序号识别
   - `01-xxx-plan.md` → `02-xxx-plan.md`
   - `phase1-plan.md` → `phase2-plan.md`
3. **依赖声明**：后续计划中声明 `依赖: [当前计划名称]`

### 自动执行提示

当满足条件时，输出：

```markdown
✅ 当前计划「[计划名称]」已完成
📊 质量评分：架构(A) | 安全(A) | 代码质量(A-) | 可维护性(A-)

📋 检测到后续计划：「[后续计划名称]」

是否继续执行后续计划？

- 输入「继续」或「是」开始执行
- 输入「暂停」或「否」等待下次执行
```

### 用户确认规则

| 用户响应     | 行为                       |
| ------------ | -------------------------- |
| 继续/是/确认 | 立即开始执行后续计划       |
| 暂停/否/等待 | 保存进度，等待用户下次指令 |
| 无响应       | 默认等待，不自动继续       |

**注意**：自动执行仅提示一次，用户无响应时不强制继续。
